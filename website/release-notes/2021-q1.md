## Web app
- `.mp4` and `.webp` files are shown with the video viewer by default.
- Redo logs are shown in the web app, with clearer error messages, and outputs with non-default input types can be redone.
- Tuning is always available from the web app.
- Project and commit links work for projects hosted on any GitLab server, based on the project's URL.

## CLI and project setup
- `qa batch` fails if pending runs it waited for have failed.
- `qa --share` is ignored when `CI=true`.
- `qa check-bit-accuracy` can compare against a commit, not only a branch, and its ignore patterns are more flexible.
- Artifacts can be listed with `globs` as well as `glob`.
- The LSF memory limit can be set with `max_memory`.
- scikit-optimize is now installed by default, so auto-optimization works out of the box.
- `qa optimize --parallel-param-sampling N` (experimental) evaluates several parameter sets in parallel, and prints the URL of the results.
- Better error messages, and less verbose output.

## Server and administration
- The backend now runs uWSGI with adaptive worker scaling and a configurable listen queue (`UWSGI_LISTEN_QUEUE_SIZE`), and containers start with a larger `net.core.somaxconn`.
- nginx serves pre-compressed `.gz` versions of output files when they exist.
- The exposed database port is configurable, and no port is hardcoded.
- The server records which user started each run.
- Fixed startup issues caused by sharing database connections between forked workers.

## Fixes
- Fixed saving artifacts when the project's storage location changed.
- Fixed a timer bug that could flood the server with requests.
