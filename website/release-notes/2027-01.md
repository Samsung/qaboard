## Web app
- Find who started a batch, redid or deleted runs, edited a run's metrics or changed milestones and roles in a project, as its developer or owner, in the project's **Admin → Audit log**, or from a batch's menu ([project audit log](/docs/user-guide/project-audit-log)).

## CLI and project setup
- Parse `qa`'s results in scripts and coding agents: `qa batch`, `qa doctor`, `qa auth status` and `qa version` take `--json`, which prints one JSON document on stdout and the rest on stderr, with the same exit codes. `qa batch --list-batches` names the batches ([JSON for scripts and agents](/docs/using-the-qa-cli#json-output)).
- Complete `qa`'s commands, options, batch names and `--input` paths in bash, zsh, fish or PowerShell: run `qa completion install` once. It reads your project's files, never the server, and `qa --help` starts about twice as fast ([shell completion](/docs/using-the-qa-cli#shell-completion)).

## Server and administration
- Find who ran, deleted or changed what in **Admin → Audit**: it now records batches started from the web app, redone and deleted runs, edited results, milestones, CI jobs started from the web app and retention cleanups, with their details. Filter by category and dates, export to CSV or JSON Lines, and send events to your SIEM with `QABOARD_AUDIT_STDOUT=1` ([the audit log](/docs/backend-admin/audit-log)).
