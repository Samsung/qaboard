## Web app
- Output cards show when each run started.
- Metrics are formatted with 3 significant digits by default, or a per-metric `precision`, and use the metrics configuration of the latest commit.
- The metrics-over-time plot shows all batches.
- Added menus to delete all the batches of a commit.
- Filtering on JSON values such as configurations is easier, and mismatch tags are clearer.
- Integrations handle CI jobs that are blocked waiting for a manual action.
- The web app no longer fails when `main_metrics` are missing.

## CLI and project setup
- `qa batch --action-on-pending` chooses what to do when matching runs are already pending: wait, reuse their results, skip, or run anyway.
- Input paths can be absolute, without specifying a database, and the default database is `/`. Database paths are normalized, and paths with many `..` are handled better.
- Long output directory names are shortened automatically.
- `QA_BATCHES_FILES` lists the batches files of the current `qa batch`, and database paths can contain environment variables.
- `qa run` warns when `run()` doesn't return a dict like `{"is_failed": False}`, and the sample project shows how to print logs in real time.
- The CLI prints YAML parsing errors and shorter URLs.
- GitLab CI statuses are updated more reliably and link directly to QA-Board for custom batches; tuning runs no longer update them.
- `qa get artifacts_branch` gives where a branch's artifacts are saved.
- Input manifests are limited to the first 200 files of an input folder.
- Added a sample script that uses the QA-Board API to get a batch's total storage.
- The `qaboard` package is now version 0.8.13.

## Server and administration
- More backend settings can be set with environment variables.
- Database backups can run as a different user.
- nginx serves more common file types (YAML, shell and Python scripts) as plain text.
- The backend handles commits with a large number of outputs better, and creates missing storage folders.

## Documentation
- Published the [introduction blog post](https://samsung.github.io/qaboard/blog/2020/08/10/introducing-QA-Board) and a [flame graphs tutorial](https://samsung.github.io/qaboard/blog/2020/06/24/flame-graphs), with a Blog link in the navigation bar.
- Added instructions to pull the docker images instead of building them, and docs on local runs and metrics.
- The docs use the new Algolia DocSearch and better meta tags.

## Fixes
- Fixed relative and absolute database paths, including with input types.
- Fixed subproject URLs when the storage root contains the subproject.
- Fixed crashes with undefined or invalid metrics, and a mixup between configurations and metrics.
- Fixed forwarded arguments, dynamic outputs and tuning runs.
