## Web app

### Image viewer
- See new and every reference you stacked together in the image viewer, each in its tile, zoomed together and compared with new or with the reference you pick as the anchor. A panel gives the pixel's values in every image and how far apart each pair is, and **Images as a contact sheet** shows each run's images in one row ([several references](/docs/user-guide/image-viewer#several-references-at-once)).

### Logged series and media
- Follow what runs log while they run, on their card: each series plotted against the reference run's, dashed, and the images, sounds, videos, tables and histograms logged at each step, with one step slider, next to the reference's. Smooth curves, use a log scale, compare by step or by time; sounds open in a new audio viewer ([logged series](/docs/user-guide/other-viewers#logged-series), [media](/docs/user-guide/other-viewers#logged-media)).
- Compare the trainings of a batch on the same plots, in the **Summary** view: one line per run, named by what tells the runs apart. Hide and show runs, hover one to bring it forward, color the runs by a parameter like the learning rate, and add their reference runs, dashed ([compare all the runs](/docs/user-guide/other-viewers#compare-logged-series)).

### Local changes
- See what code a run from someone's computer ran: runs with uncommitted changes are tagged **uncommitted +40 −12**, which opens the changed files, the patch, the unpushed commits and the reference run's changes side by side. Batches that ran the same code say it once, `changes:local` filters the runs, and **Redo** warns that it runs the commit without them ([what code a run ran](/docs/user-guide/local-changes)).

### Run cards
- See more of each visualization: run cards take the page's whole width, one under the other, with room between their visualizations, and HTML reports fill the card, up to the window's height. Projects that set `outputs.style.width` keep their cards side by side ([card sizes](/docs/visualizations#styles)).

### Logs
- See every command that started a batch at the top of **Logs**, from QA-Board, a terminal or the CI, with what was typed, the batches it ran and whether their definitions changed since the reference's. **Run again…** fills in **Run Tests / Tuning** with its batches as they were then, or gives them as a YAML file ([batch commands](/docs/user-guide/logs#batch-commands), [run a batch again](/docs/user-guide/logs#run-again)).
- See how much memory, CPU and GPU each run used, and plot it over time, in **Logs** and in its **⋯** menu. A run done again after its job was killed for using too much memory keeps what the attempt used, and its runner's log, like LSF's report in *log.attempt1.lsf.txt* ([memory, CPU and GPUs](/docs/system-metrics), [logs](/docs/user-guide/logs)).

### Tuning
- See how to get missing artifacts back: when a commit's artifacts are missing, **Run Tests / Tuning** says QA-Board can ask your CI to recreate them ([recreating artifacts](/docs/storage/deleting-old-data#recreating-artifacts)).

### Metrics
- Find the runs that changed most: click a metric in the **Metrics Diff** to sort the runs by the size of their change vs their reference run, better or worse, or pick **Change of …** in **Sort runs** ([Metrics Diff](/docs/user-guide/metrics#metrics-diff)).

### Trends
- Follow tests and benchmarks over a branch's commits on **Trends**, the History page's new name (prototype): what fails and since when, flaky and slower tests, benchmarks that moved. A test re-run in a second report counts once, flaky if it passed; totals say when the same tests ran in several configurations. Above a branch's commits, the chart is now a **Trends** card ([Trends](/docs/user-guide/trends)).

## CLI and project setup

- **Before you upgrade**:
  - `qa run` and `qa batch` now always show results in QA-Board, from your computer too, in a batch of your own: you no longer need `--share`. `qa --offline` keeps results in *output/* without contacting the server. Upgrade `qaboard` on your computers and on the machines that run your batches at the same time ([see results in the web app](/docs/using-the-qa-cli#see-results-in-the-web-app)).
  - Set `project.reference_branch` in *qaboard.yaml* to keep comparing with `master`: without it, the reference is now your repository's default branch, else `main` ([references](/docs/references-and-milestones)).

### Results without a shared storage
- Save files other tools wrote as a run, with `qa upload` (experimental): `qa upload junit.xml pytest.benchmarks.json` in CI brings in test reports, benchmark files or profiles from any language, with metrics Trends follows over commits ([tests and benchmarks over time](/docs/tests-and-benchmarks-over-time)). Give your own metrics a `group` to see them there too ([grouping metrics](/docs/computing-quantitative-metrics#grouping-metrics)).
- Send runs' files to the server over HTTP where the shared storage isn't mounted, like GitHub-hosted runners (experimental), with `storage: upload`. It needs a token and a server that accepts files. Projects without any `storage` setting now do this: set `storage`, or install your site package, to keep using the shared storage ([without a shared storage](/docs/storage/uploads)).
- Start runs and tuning from the web app without a shared storage: `qa save-artifacts` sends the commit's artifacts to the server, which runs batches from them on Kubernetes, whose pods download them, or on its own machine if its admins allow it ([artifacts without a shared storage](/docs/storage/artifacts#uploaded)).

### Runs from Python
- Create runs from your own code, without `qa run` or a *qaboard.yaml*: `qaboard.start_run()` in a training loop, a notebook or a script, then `run.log({"loss": loss, "samples": [qaboard.Image(x)]}, step=step)` logs values and media at each step: images with boxes, sounds, videos, tables, histograms. `resume=True` continues an interrupted run ([log from your code](/docs/log-from-code), [media](/docs/log-from-code#media)).
- Log to QA-Board with the code you wrote for W&B or MLflow (experimental): run `python -m qaboard.integrations.wandb train.py`, or set `MLFLOW_TRACKING_URI=qaboard:` (`qaboard+<your MLflow URI>` keeps your MLflow server too). Their media show at their step; what QA-Board can't keep, like masks or a model registry, is listed when the run ends ([from W&B](/docs/from-wandb), [from MLflow](/docs/from-mlflow)).

### Local changes
- Know what code your local runs ran: `qa run`, `qa batch` and `start_run()` save the patch of your uncommitted changes with each run, new files and unpushed commits included, and `qa restore <run>` gets that code back in a branch. Choose `summary` or `off` with `outputs.local_changes`; nothing is recorded in CI ([local changes](/docs/local-changes)).

### Memory, CPU and GPUs
- Measure what runs use of their machine, with nothing to set up: `qa run` and `start_run()` sample their memory, CPU and GPUs every 5 seconds, send QA-Board the peaks, and save the samples in *system.series.json* for plots. `outputs: {system_metrics: false}` turns it off. Check bit accuracy with this `qa` or a later one: older ones don't ignore that file ([memory, CPU and GPUs](/docs/system-metrics)).

### Batches
- Keep what your batches ran: `qa --share batch` and `qa batch` in CI send QA-Board the batches as they were defined when they started, with only the batches they ran and the aliases that reached them, nested ones too. Batches started from the web app read the same kind of file, instead of copies of the whole shared and private batch files ([what is saved](/docs/user-guide/logs#run-again)).

### Scripts, agents and the HTTP API
- Have QA-Board start a batch on a pushed commit from a script, a CI job or a coding agent: `qa --label <name> batch --commit <commit> <batch>` (and `qa optimize --commit`) runs it as the web app's **Start** does, from the commit's artifacts, prints the batch's page and returns. Send batch files you didn't commit with `--batches-file` ([start batches from a terminal](/docs/tuning-from-the-webapp#from-the-command-line)).
- Point a coding agent at [llms.txt](https://samsung.github.io/qaboard/llms.txt): every docs page, by audience, with what it's for ([agents](/docs/agents)).

## Server and administration

- **Before you upgrade**:
  - Give tokens to whoever sends results: servers now refuse results without one (`ingest.auth` is `token` by default). People run `qa auth login`, CI jobs get a token or [sign in as themselves](/docs/ci-integration#ci-without-secrets). Until they do, set `ingest.auth` (or `QABOARD_INGEST_AUTH`) to `warn`; batches started from the web app through LSF need it too ([results sent by qa](/docs/backend-admin/user-management#results-sent-by-qa)).
  - Runs' HTML, SVG and XML files are sandboxed by default: their scripts only run in QA-Board's run cards, in an origin of their own, not when opened in a tab. `QABOARD_SANDBOX_HTML=false` brings back the old behavior ([HTML reports](/docs/viewers#html-reports)).
  - Files under `/s/` and images under `/iiif/` now follow projects' visibility with the default nginx configuration and the Helm chart (`proxy.restrictFiles` is now `true`). With your own nginx configuration, add `include snippets/qaboard-iiif-auth.conf;` to the image server's location ([keep it safe](/docs/backend-admin/uploads#security)).
  - Tokens last at most a year (`tokens.max_lifetime_days`): new tokens can't be created without an expiry date. Existing ones keep theirs.
  - Set `QABOARD_TUNING_RUNNER` to keep starting batches from the web app (tuning, redo, `qa batch --commit`): unset, the server no longer runs them in its own container, as the backend's account. `kubernetes` or `lsf` are safer than `local` or `celery`, which **Admin → Settings** now warns about. Unless it is one of those two, the server also no longer runs a project's own `iter_inputs` to list a batch's tests: the form says so and still starts the batch ([where batches run](/docs/backend-admin/runners#security)).
  - Add `include snippets/qaboard-app-headers.conf;` to the `/` and `/assets/` locations if your site has its own nginx configuration, as in `services/nginx/conf.d/qaboard.conf`: other websites can then no longer show the web app in a frame, and nginx no longer sends its version.
  - If your site has its own nginx configuration and takes uploaded files, copy the upload and batch-log locations from `services/nginx/conf.d/qaboard.conf` and include `snippets/qaboard-files-server.conf` in the `server`: without it, nginx now refuses uploads, restricted files and admin pages instead of letting them through unchecked.
  - With the Helm chart, only the proxy can reach the backend's uWSGI port (`backend.networkPolicy.enabled`, on by default, where the cluster enforces NetworkPolicies): set it to `false` if something else of yours talks to that port ([uploads](/docs/backend-admin/uploads#security)).

### Local changes
- Choose whether the server keeps your users' code: runs from people's computers save the patch of their uncommitted changes with their files, and `runs.local_changes: summary` (in **Admin → Settings**, or `QABOARD_LOCAL_CHANGES`) keeps only the changed files' names and counts ([local changes](/docs/backend-admin/settings#local-changes)).

### Results without a shared storage
- Let runs send their files to the server over HTTP (experimental), on by default in `/mnt/qaboard` (`QABOARD_UPLOAD_ROOT` for your own roots, `off` turns it off), and give projects their own mounted bucket in **Admin → Storage**. Read [Keep it safe](/docs/backend-admin/uploads#security) before such a server faces the internet ([storage locations](/docs/backend-admin/uploads#storage-locations)).
- Batches started from the web app for projects without a shared storage get a token of whoever started them that only changes that batch's results, and ends with the batch. On Kubernetes it is in the driver pod's environment, readable by whoever can read the namespace's ConfigMaps: keep one namespace per team ([uploads](/docs/backend-admin/uploads#security)).
- Fail runs that stop reporting, e.g. when their machine is killed: runs from the new `qa` and `start_run()` report every two minutes, and are failed after 15 minutes of silence ([runs that stop reporting](/docs/backend-admin/storage#silent-runs)).

## Fixes
### Web app and HTTP API
- Fixed adding metrics to a finished run from a script or the HTTP API failing with a server error ([add metrics to runs](/docs/http-api#add-metrics)).
- Filter **Runs activity** and **Storage usage** by their totals from the keyboard, and hear what status, lock and info icons mean with a screen reader.
- Fixed API calls on runs or batches with an id that isn't a number, or without a batch label, failing with a server error: they now answer 404 or 400 with a message, and a batch is never saved without a label. Asking for the value of a pixel outside an image answers 400 too, instead of an error, or of a pixel from the other edge for negative coordinates.
- Fixed deleting runs failing on folders their owners made private (like `0700`) or read-only, or on someone else's files in them. When a file still can't be deleted, the error says which folder blocks it, its permissions and who can delete it.

### CLI and runs
- Fixed `qa` giving up on telling QA-Board how a run ended after one failed request: it tries again for about two minutes when the server restarts or a load balancer in front of it fails, and asks you to sign in again when a token is invalid, expired or revoked.
- Fixed bit-accuracy manifests dropping the bytes of text files that aren't valid UTF-8, and changing the line endings of files with NUL bytes: binary outputs are compared exactly again in projects that set `bit_accuracy.binary` ([line endings](/docs/bit-accuracy#line-endings)).
- Find what your executables and native code print in the run's *log.txt*, not only what Python prints: no need to capture their output and print it anymore. They still write to a terminal, so colors and progress bars stay. On Windows, *log.txt* still only has what Python prints ([running an executable](/docs/running-your-code#run-an-executable)).
- Fixed `qa` crashing on Windows when project files, like *qaboard.yaml* or batch files, have accents or other non-ASCII characters. Fixed `qa run` failing, or warning about a `postprocess` you don't have, when `run()` returns metrics without `is_failed`, and `qa` crashing on a *qaboard.yaml* without `project.url`.

### Server
- Fixed anyone being able to rewrite a run's manifest without its files' hashes, which broke bit-accuracy checks against it: refreshing a manifest now needs signing in. XML files are sandboxed like HTML and SVG, and files under `/s/` are sent with `X-Content-Type-Options: nosniff` ([keep it safe](/docs/backend-admin/uploads#security)).
- Fixed batches started from the web app having their results refused on servers that require tokens (`ingest.auth: token`): they get a token of whoever started them. QA-Board refuses to start them with LSF, whose jobs can't get it: start those from CI or a terminal after `qa auth login` ([results sent by qa](/docs/backend-admin/user-management#results-sent-by-qa)).
- Fixed the Helm chart's backend failing to start after `runners.kubernetes` is turned off again ([Kubernetes](/docs/backend-admin/kubernetes#start-batches-from-the-web-app)).
