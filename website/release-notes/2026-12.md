## Web app

### Logged series
- Follow what runs log while they run, like a training's loss at each step: their card plots each series, the reference run's dashed on the same axes, and keeps up with runs that are still running. Smooth noisy curves, switch to a logarithmic scale, and compare by step or by time ([logged series](/docs/user-guide/other-viewers#logged-series)).
- Compare the trainings of a batch on the same plots, in the **Summary** view: one line per run, named by what tells the runs apart. Hide and show runs, hover one to bring it forward, color the runs by a parameter like the learning rate, and add their reference runs, dashed ([compare all the runs](/docs/user-guide/other-viewers#compare-logged-series)).

### Tuning
- See how to get missing artifacts back: when a commit's artifacts are missing, **Run Tests / Tuning** says QA-Board can ask your CI to recreate them ([recreating artifacts](/docs/storage/deleting-old-data#recreating-artifacts)).

## CLI and project setup

### Runs from Python
- Create runs from your own code, without `qa run` (experimental): `qaboard.start_run()` in a training loop, a notebook or a script, then `run.log({"train/loss": loss}, step=step)`, `run.log_metrics()`, `run.log_params()` and `run.log_artifact()`. The run shows in the web app like a `qa run`, while it runs; `resume=True` continues one that was interrupted ([log from your code](/docs/log-from-code)).
- Plot series written by programs in any language: save a *series.jsonl* in the run's folder, one JSON object per line with the step and the values, and list it in your visualizations ([the format](/docs/viewers#series)).

### Scripts, agents and the HTTP API
- Have QA-Board start a batch on a pushed commit from a script, a CI job or a coding agent: `qa --label <name> batch --commit <commit> <batch>` (and `qa optimize --commit`) runs it as the web app's **Start** does, from the commit's artifacts, prints the batch's page and returns. Send batch files you didn't commit with `--batches-file` ([start batches from a terminal](/docs/tuning-from-the-webapp#from-the-command-line)).
