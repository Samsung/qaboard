## Web app

### Logged series
- Follow what runs log while they run, like a training's loss at each step: their card plots each series, the reference run's dashed on the same axes, and keeps up with runs that are still running. Smooth noisy curves, switch to a logarithmic scale, and compare by step or by time ([logged series](/docs/user-guide/other-viewers#logged-series)).
- Compare the trainings of a batch on the same plots, in the **Summary** view: one line per run, named by what tells the runs apart. Hide and show runs, hover one to bring it forward, color the runs by a parameter like the learning rate, and add their reference runs, dashed ([compare all the runs](/docs/user-guide/other-viewers#compare-logged-series)).

### Run cards
- See the test reports, benchmark files and profiles of runs created with `qa upload` or `qaboard.start_run()` on their cards, without anything in *qaboard.yaml*: the files are recognized by their names, like *junit.xml* or *\*.benchmarks.json* ([what you can upload](/docs/upload-results#files)).

## CLI and project setup

### Results without a shared storage
- Save files other tools wrote as a run, with `qa upload` (experimental): `qa upload junit.xml` in a CI job brings in a test report, a benchmark file or a profile, without a `run()` function or a *qaboard.yaml*, from any language. Test reports and benchmark files give the run its metrics ([upload results from any tool](/docs/upload-results)).
- Send runs' files to the server over HTTP where the shared storage can't be mounted, like GitHub-hosted runners or a laptop (experimental): leave `storage` out of *qaboard.yaml*, or set `storage: upload` or `QA_STORAGE=upload`. The log is sent while the run goes on, the rest when it ends. It needs a token, and a server that accepts files ([without a shared storage](/docs/storage/uploads)).

### Runs from Python
- Create runs from your own code, without `qa run` (experimental): `qaboard.start_run()` in a training loop, a notebook or a script, then `run.log({"train/loss": loss}, step=step)`, `run.log_metrics()`, `run.log_params()` and `run.log_artifact()`. The run shows in the web app like a `qa run`, while it runs; `resume=True` continues one that was interrupted ([log from your code](/docs/log-from-code)).
- Plot series written by programs in any language: save a *series.jsonl* in the run's folder, one JSON object per line with the step and the values, and list it in your visualizations ([the format](/docs/viewers#series)).

## Server and administration
- Let runs send their files to the server over HTTP (experimental): set `QABOARD_UPLOAD_ROOT` to a folder of the results storage (`results.uploads: true` with the Helm chart). Files always need a token; before exposing the server, also turn on `QABOARD_SANDBOX_HTML`. The page covers limits, and object storage like S3 through a mounted file system ([accept results over HTTP](/docs/backend-admin/uploads)).
