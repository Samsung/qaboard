## Web app

### Metrics
- See all the metrics of your runs, even those your project didn't declare: in the Summary, the Metrics Table, the Metrics Diff, the run cards and the History page. Before, metrics missing from the metrics file were hidden. See [metrics](/docs/computing-quantitative-metrics#what-qa-board-shows-by-default).
- Tell improvements from noise at a glance: when QA-Board doesn't know whether higher or lower is better, it shows changes in neutral colors instead of guessing. The Summary's changes are gray, and the Metrics Diff shades cells in blue by how much they changed. Hover a metric's name to see why, and follow the Summary's link to declare it ([user guide](/docs/user-guide/commit-page#summary)).
- Spot outliers in the Metrics Table: metrics without a target are shaded in blue, by how each value ranks among the runs.
- Get a useful Summary without configuration: when the project doesn't choose `summary_metrics`, it shows the metrics that changed the most vs the reference.
- See a run's first metrics on its card when the project doesn't choose `main_metrics`, and plot any metric of the runs on the History page.

## CLI and project setup

### Declaring metrics in your code
- Declare your metrics where your code computes them instead of in a metrics file: return `Metric(value, suffix=" ms", smaller_is_better=True, target=15)`, call `define_metric("psnr", smaller_is_better=False)` next to the code that computes it, or write a *metrics_definitions.json* next to *metrics.json* from any language. QA-Board keeps the definitions with each commit. See [declaring metrics](/docs/computing-quantitative-metrics#declaring-metrics).
- Keep your metrics file while you move to definitions in code: both work together, the code winning. Metrics files only need to list the metrics to show by default, and listed metrics don't have to be declared.
- Write `smaller_is_better: null` in a metrics file for metrics where neither is better, like counts: their changes stay neutral.
- Check *metrics_definitions.json* files in your editor with their JSON schema ([project setup](/docs/project-init#checking-qaboardyaml-and-batch-files-in-your-editor)).

### Quality gate
- `qa gate` reads which way is better from the metrics your code declares too. Regression rules on a metric that doesn't say fail with an error that tells you how to declare it ([quality gate](/docs/quality-gate#rules)).
