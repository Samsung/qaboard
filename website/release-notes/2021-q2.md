## Web app
- The text viewer can switch between side-by-side and inline diffs, without animations, and says when both files are identical.
- Batch logs have a "scroll to bottom" button.
- Batches can be soft-deleted: their output files are removed but their metadata and metrics are kept.
- The table view has a clearer sort menu and fewer unused columns, and metrics with `target_passfail` are shown green or red against their target.
- The project list can be filtered, and loads faster because it no longer downloads every project's data.
- Milestones can be filtered.
- Tuning analysis can use any configuration parameter, not only tuning parameters, shows nested parameters, and has a better UI.
- The artifacts panel has a better UI.
- Project avatars from private GitLab repositories are proxied by the server, which also avoids mixed-content issues.

## CLI and project setup
- `qa batch --action-on-existing=assert-exists` fails when matching runs don't exist, which helps scripts look up past results, for instance with `CI=true GIT_COMMIT=...`.
- `qa check-bit-accuracy --strict` also fails when a file exists in only one of the runs being compared. Input manifests are always written.
- Auto-optimization reads `parallel_sampling` from the optimization configuration file.
- Tuning parameters are passed to `qa batch` on the command line instead of through files, so past tuning runs can be reproduced and permission issues are avoided.
- `QA_USER` overrides the user name recorded for runs.
- Parsing errors in configuration files are no longer ignored, and missing runs are reported with more details.

## Server and administration
- Added LDAP settings (`QABOARD_LDAP_ENABLED`, `QABOARD_LDAP_HOST`...) and a `SECRET_KEY` for login sessions.
- Jenkins credentials are now given with a single `JENKINS_AUTH` JSON variable, which supports several Jenkins servers. It replaces `JENKINS_USER_NAME`, `JENKINS_USER_TOKEN` and `JENKINS_USER_CRUMB`.
- `GITLAB_AUTH` gives the credentials used to show avatars of private GitLab projects.
- Added an API to update a run's data (`PUT /api/v1/output/:id`).
- `PGHOST` can be set from the environment, and the database container gets more shared memory.
- CORS headers are always sent, even on errors.
- Triggering GitLab pipelines with many jobs works, thanks to pagination.
