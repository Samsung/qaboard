## Web app
- Added the "What's new" panel: the release notes, newest first, with a search box. The link `/#whats-new` opens it, handy to share in a chat.
- The "What's new" dialog pops up once a month (or quarter) is over, with everything that changed in it. The notes of the current month show in the panel as a preview, tagged "In progress".
- The sidebar's help button opens the new [user guide](/docs/user-guide/overview).
- The Logs view lets you filter runs (all, failed, running), tags failed runs with the reason (e.g. "LSF: out of memory"), and stays fast with hundreds of runs.
- In the Logs view, each run fits on one line, with its configuration in short and buttons to open its output directory, redo, mark as failed or delete it. The full configuration shows when you open the run's logs, and the logs no longer get wider than the window.
- The sidebar's Logs entry shows how many runs failed, or are still running.
- Switch between a run's `log.txt`, `log.lsf.txt` and `log.dask.txt`. For LSF runs, a summary shows the exit reason, host, run time and memory used vs requested, with hints that point to the batch's `lsf:` options.
- Batches started from QA-Board (tuning, "Run Tests") show whether `qa batch` is waiting for LSF, running, failed (with the error) or didn't start any run, with a link to its logs.
- Links to commits and projects use your server's git host instead of a hardcoded one, and the "Quotas" links only show when the server has a quota dashboard.
- The error page links to your server's support page.

## CLI and project setup
- At SIRC, upgrading `qaboard` now requires also installing `qaboard-site-sirc`, see the [installation instructions](/docs/installation). Site packages provide a base `qaboard.yaml` that every project's configuration is merged on ([site defaults](/docs/project-init#site-defaults)): `qa init` shows the inherited values instead of overriding them.
- LSF runs write their output live to `log.lsf.txt`, with LSF's job report at the end. `qa batch` no longer passes an LSF queue or project when none is set, and fails fast when `bsub` is missing.
- `qa init` creates a configuration that runs locally: LSF is commented out, and storage defaults to `/mnt/qaboard` like the server.
- The CLI reads your `QA_TOKEN` from `$QA_TOKEN` or `~/.qaboard/secrets.yaml`, and warns if other users can read that file.
- `QABOARD_API_VERIFY` controls the TLS verification of the CLI's requests to the server: `true` (the default), `false`, or the path to a CA bundle.
- Site packages (company-specific plugins) are no longer ignored on Python 3.8 and 3.9.
- The package now includes the `qatools` compatibility package, and update checks no longer suggest a site-specific install command to everyone.
- Configure the Windows runner's PowerShell `$ErrorActionPreference` per job (the batch's `error_action:` option) or with the `QA_RUNNER_ERROR_ACTION` environment variable (default `Stop`).

## Server and administration
- Zero-downtime deploys with [deployments/deploy.py](/docs/backend-admin/deployment): images tagged per version, several backend replicas behind nginx, rolling updates, `rollback`, `status` and `restore-db`.
- `deploy.py seed-db` fills a staging database with only production's recent data.
- A [Helm chart](/docs/backend-admin/kubernetes) to run QA-Board on Kubernetes.
- The backend has a `/api/v1/health` endpoint, shuts down gracefully, and keeps working when redis is down.
- Security: actions that run commands (redo, tuning, stopping or deleting batches...) now require a login and run as the logged-in user, and their inputs are escaped. See SECURITY.md.
- Security: the server only writes, deletes or runs code in the folders listed in `QABOARD_STORAGE_ROOTS` (default: `/mnt/qaboard`), and refuses results stored elsewhere. **If your projects store results in other folders, set it before upgrading** (see [environment variables](/docs/deploy#optional-environment-variables)).
- Set `QABOARD_WEBHOOK_SECRET`, and the same secret in your GitLab and GitHub webhooks, so that only they can send push events. For GitHub Enterprise, list its hostname in `QABOARD_GITHUB_HOSTS` (see [environment variables](/docs/deploy#optional-environment-variables)).
- Each batch started from QA-Board gets its own folder with its scripts and logs, under the batch's `qaboard-batches/`.
- The web app links to the docs served by your server at `/docs/`, which match its version, instead of the public website. Set `QABOARD_DOCS_ROOT` to use another docs site.
- The git host, quota dashboard and support links are configurable (`GITLAB_HOST`, `QABOARD_QUOTA_URL_TEMPLATE`, `QABOARD_SUPPORT_URL`).

## Documentation
- New [user guide](/docs/user-guide/overview) for people who use the web app every day.
- New runbooks for deployments, rollbacks and Kubernetes.
- Release notes going back to 2017, on the website and in the app.
- Many pages updated to match the code, and features that were never documented: GitHub webhooks, API tokens, batch options, bit-accuracy manifests, auto-optimization...

## Fixes
- With LSF job arrays and the Dask runner, `qa run` no longer deletes the log file its output goes to: errors are no longer lost.
- The tuning form shows a readable error instead of the server's raw response.
- A stuck run's "Mark as Finished" action is now labelled "Mark as Failed", which is what it does.
- Security: marking a run as failed or deleting it now requires a login.
- Deleting results no longer deletes the contents of folders that they link to.
- The batch selector no longer jumps back to the top while you scroll it, and its keyboard navigation works again. It now opens on the selected batch, marked with a check.
- Switching to a branch you had opened in a previous visit no longer crashes the commits list ("setHours is not a function").
- Runs started from a `git worktree` checkout are saved under their commit, instead of their branch name. Submodules with a relative `.git` pointer also work.
- The image viewer's diff threshold slider no longer jumps to its maximum and gets stuck: it moves step by step after you turn the diff on.
