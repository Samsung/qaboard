For teams shipping LLM or agent features who want their evals reviewed like any other part of the product.

**A pass rate that moves by two points doesn't say what broke.** A prompt or a tool description changes, and the
agent's behavior changes on tasks nobody looked at: it skips a confirmation, or costs twice as much per answer.
QA-Board puts each task's result next to the reference's, with the transcripts diffed, and fails CI on the one thing
that must never happen.

<Shot id="commit/transcript-diff" />

## What it changes for your team
- **Task by task, against the reference.** Pass or fail, unsafe actions, turns, tokens and cost for every task, in the
  Summary and the Metrics Diff, on every commit.
- **The transcripts, diffed.** The request, each tool call and its result, the answer: what the agent does differently
  shows line by line.
- **Your report per task.** Your code writes HTML: each check, passed or failed, and why.
- **A gate on what must never happen.** `qa gate` (experimental) fails CI when any task has an unsafe action, or when
  the pass rate drops, whoever made the change.
- **Sweeps over prompts and models.** Start them from the browser, and compare pass rates and costs side by side.
- **One place for all of your product's quality.** The same server and the same review cover your models, your
  services and your test suites, not only the agent.

## See it in action
The pictures come from a demo assistant for robot fleet operators, right after the team's coding agent shortened the
tools' descriptions and turned off a confirmation check.

### The assistant stopped asking
Transcripts diffed with the reference's (above): the reference's reboot waits for the operator to confirm; after the
change, it runs without asking, even after the operator said no.

### Each check, and why it failed
The task's report, written by your code: each check passed or failed and why, the unsafe actions, the conversation,
tokens and cost. QA-Board shows it in the run's card, next to the reference's.

<Shot id="commit/agent-report" />

### Gate the whole eval set
A run's metrics are 0 or 1 for `passed`, so the gate's rules aggregate them over the batch's tasks: `aggregate: max`
(no task may have an unsafe action) and `aggregate: mean` (the pass rate).

<RepoFile path="examples/agent-evals/qaboard.yaml" title="qaboard.yaml" section="gate" />

The verdict goes where the coding agent's change is reviewed: with `--post-comment github` (or `gitlab`), `qa gate`
posts its table on the pull request, and says when the change loosens the gate's own rules or when tasks only passed
after being run again. Rules your project's owners set in the web app hold whatever the commit says (see
[comment on pull requests](/docs/quality-gate-pull-requests) and
[rules a commit can't change](/docs/quality-gate#project-rules)).

## How it's set up {#the-configuration}
Each task is a YAML file, `tasks/<category>/<name>.yaml`: the request, the facts the agent can look up, the checks.
The transcripts are text files, diffed by the text viewer; the reports are HTML.

<RepoFile path="examples/agent-evals/qaboard.yaml" title="qaboard.yaml" section="inputs,outputs" />

Conversations are memoized by everything they depend on (the model file, the prompt, the tools, the flags, the task
and the agent's code): a commit that doesn't change them reuses the identical conversation, which keeps CI fast and
reviews stable.

## Try it on the demo {#run-this-example}
In [`examples/agent-evals`](https://github.com/Samsung/qaboard/tree/master/examples/agent-evals), an operators'
assistant answers requests about a simulated robot fleet by calling tools: list the robots, read their battery and
status, assign a mission, reboot a robot, search the maintenance log. It runs on a small local model with llama.cpp on
the CPU and greedy decoding, so there are no keys, nothing is billed, and the same inputs give the same transcripts.
Each run is one scripted task: lookups, multi-step requests, safety, and ambiguous requests.

<details>
<summary>The story the pictures tell</summary>

1. A bigger model passes more tasks for about the same cost.
2. "Think step by step" more than doubles the tokens and passes no more tasks; a compact prompt with example
   conversations beats both, as a sweep over the prompts shows.
3. The coding agent shortens the tools' descriptions and turns off the confirmation check: the assistant reboots
   robots without asking, even after the operator said no. The gate fails on the unsafe actions.
4. Detailed descriptions and the confirmation check come back, the gate passes, and the release is a milestone.

</details>

You need Python 3.10 or later. The first run downloads the two models (about 1 GB, checked by SHA-256); a task takes
a few seconds on 4 cores.

```bash
cd examples/agent-evals
pip install qaboard -r requirements.txt
python qa/build.py              # downloads the models, once
qa run --input safety/reboot-without-asking.yaml
qa batch ci                     # 12 tasks, 3 per category
```

Without `--share`, results stay in `output/`. To see them in the web app, run `qa --share batch ci`. With the
[quickstart](/docs/get-started/quickstart#save-results-from-your-computer)'s server, first
`export QABOARD_URL=http://localhost:5151 QA_STORAGE=/tmp/qaboard`. See the example's
[README](https://github.com/Samsung/qaboard/tree/master/examples/agent-evals#readme) for the flags, the 24 tasks and
the prompt sweep.
