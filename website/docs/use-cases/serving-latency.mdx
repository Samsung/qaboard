## The problem
Latency is a distribution, not a number. A change can make the median faster and the tail much slower, and the tail is
what users and timeouts see. Measurements are noisy, so one run proves little: you need repeats, the same load
profiles on every commit, and a way to see where the time went.

## The example
A small inference gateway, in Rust: a request queue, dynamic batching, a pool of workers running a CPU model, and a
result cache. An open-loop load generator sends it requests at a fixed rate, with steady, bursty, heavy-tailed and
ramping profiles. Each run measures the latency percentiles from p50 to p99.9, throughput, CPU per request, and how
long requests waited in the queue, for a batch or for a lock, and records CPU samples for a flame graph.

Its story:
1. The team's coding agent adds a shared result cache: p50 gets faster, p99 much slower. The quality gate fails.
2. The flame graph diff shows the time going to the cache's lock.
3. Sharding the cache by key fixes p99 and keeps the p50 gain. A tuning sweep then picks the batching settings.
4. Later, a commit that copies payloads makes p99 worse on the heavy-tailed profile only: the median over all
   profiles barely moves, and History finds it.

## The configuration
Planned, from the example's spec. Plots set their traces' colors, so the web app draws the reference dashed and faded
when `side_by_side: false` overlays them.

```yaml title="qaboard.yaml (planned)"
outputs:
  metrics: qa/metrics.yaml
  visualizations:
    - name: Latency percentiles (log tail)
      path: latency_cdf.plotly.json
      side_by_side: false              # overlay: the reference is drawn dashed and faded
    - name: Where the time goes
      path: breakdown.plotly.json      # queue, batch wait, lock wait, compute at p50/p90/p99/p99.9
    - name: Throughput vs p99
      path: sweep.plotly.json          # ramp runs only
      side_by_side: false
    - name: CPU flame graph
      path: cpu.flame.json
    - name: CPU per core
      path: cores.plotly.json
      default_hidden: true
```
