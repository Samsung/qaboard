## The problem
One mAP number hides where a model got worse. Quantizing a detector to int8 makes it faster, and the average barely
moves, while small objects quietly disappear. You need metrics per class and per object size, on slices of your data,
next to the reference model's, and the images where it went wrong.

## The example
An off-the-shelf detector (torchvision's SSDlite, BSD-licensed) runs on CPU with ONNX Runtime, in fp32 and in int8,
at several input sizes. It's evaluated on four slices of images: indoor, outdoor, warehouse, and small objects. Each
run measures COCO-style AP, AP per object size and per class, recall on small objects, and latency.

Its story:
1. The first int8 model is much faster, and its AP on small objects drops by a fifth or more.
2. Per-channel weights and better calibration shrink the gap.
3. `qa optimize` searches the quantization settings; the Analysis view shows which ones matter.
4. The tuned model ships as a milestone, the next reference.

## The configuration
Planned, from the example's spec. `:image` in a path gives a slider over the slice's images, synced across runs.

```yaml title="qaboard.yaml (planned)"
outputs:
  metrics: qa/metrics.yaml
  visualizations:
    - name: Detections
      path: "images/:image.jpg"          # a synced slider over the slice's images
    - name: Precision-recall
      path: pr.plotly.json               # one curve per class: the reference is dashed
      side_by_side: false
    - name: Recall by object size
      path: size_recall.plotly.json
      side_by_side: false
    - name: Report
      path: report.html
```
