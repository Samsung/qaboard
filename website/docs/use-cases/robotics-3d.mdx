For robotics, perception and automotive engineers whose outputs are trajectories, maps and sensor streams.

**An average error doesn't say where the robot got lost, or why.** A change that helps slow, careful driving can make
fast turns drift, and one number over a few recorded sequences hides it. QA-Board shows each sequence's trajectory
against the ground truth and the reference's, the map it built, and what the sensors saw when it went wrong.

<Clip id="commit/video-sync" />

## What it changes for your team
- **Every sequence, against the ground truth and the reference.** Trajectories per axis and in 3D, with the error
  over time, for each sequence, on every commit.
- **The map, in 3D.** Orbit the point cloud the robot built, against where the points really are.
- **The sensors, in sync with the result.** Sensor videos play next to the reference's, frame by frame, so
  you see the moment the estimate leaves the truth.
- **Regressions caught per sequence.** History follows a trajectory metric commit after commit; `qa gate`
  (experimental) fails CI when one sequence gets much worse, even when the average doesn't.

### And everything else your code writes
The error over time is a Plotly figure with the reference's curve dashed on the same axes; a top-down map over the
true layout is an image, compared with the [image viewer](/docs/user-guide/image-viewer). **History** follows the
error of one sequence across commits, so the step where the fast figure-8 started drifting shows. See
[History](/docs/user-guide/history-and-dashboards).

## How it's set up {#the-configuration}
Each sequence is a folder with a `sequence.yaml`: the path and the warehouse's seed. The 6DoF viewer reads tab-separated
poses, with the ground truth in `GT_final.txt`; the point cloud viewer reads PCD files, with an optional ground truth.

<RepoFile path="examples/robotics-3d/qaboard.yaml" title="qaboard.yaml" section="inputs,outputs,gate" />

A run is memoized by the code, the flags, the sequence and the seed: a commit that doesn't change the odometry reuses
the identical run, which keeps CI fast. Do the same for long simulations, and say so in the run's log.

## Try it on the demo {#run-this-example}
In [`examples/robotics-3d`](https://github.com/Samsung/qaboard/tree/master/examples/robotics-3d), a warehouse robot
drives six simulated sequences: aisles, a loop around shelves, two figure-8s (one twice as fast), a docking approach
and a long corridor. Its depth camera and IMU are simulated, so the ground truth is exact. The odometry registers each
depth frame with point-to-plane ICP, started from the IMU's prediction, and closes loops with a pose graph. Each run
measures the absolute trajectory error (ATE), the relative pose error per meter, the drift at the end and the time per
frame.

<details>
<summary>The story the pictures tell</summary>

1. The first release has no loop closure.
2. Loop closure lands with a threshold that accepts matches with 30% overlap: they slide along the rows of identical
   shelf bays, and on the figure-8s the trajectory jumps meters away. The quality gate fails; raising the threshold to
   60% keeps the real loop closures, which cut the error on the loops.
3. A change that trusts ICP over the IMU makes the figure-8s drift in their turns. History on the figure-8 shows the
   step, the gate fails, and the change is reverted.
4. Keyframes every 0.6 m instead of 0.3 m make it faster and better; a tuning sweep backs the choice.

</details>

You need Python 3.10 or later and FFmpeg (for the videos). The first run generates the sequences' ground truth (about
20 s); a run takes 15-40 s.

```bash
cd examples/robotics-3d
pip install qaboard -r requirements.txt
qa run --input sequences/figure8-fast
qa batch ci                     # the 6 sequences
```

Without `--share`, results stay in `output/`. To see them in the web app, run `qa --share batch ci`. With the
[quickstart](/docs/get-started/quickstart#save-results-from-your-computer)'s server, first
`export QABOARD_URL=http://localhost:5151 QA_STORAGE=/tmp/qaboard`. See the example's
[README](https://github.com/Samsung/qaboard/tree/master/examples/robotics-3d#readme) for the flags and the tuning
sweep.
