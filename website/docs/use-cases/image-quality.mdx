For camera, ISP and imaging teams, and for embedded teams that hand an algorithm over to silicon.

**A better PSNR doesn't mean a better image.** Halos, plastic textures and color shifts get past the metrics, and get
caught by customers. QA-Board runs your pipeline on every commit and puts its images next to the release's, in sync
down to the pixel, under the metrics that go with them. Your team sees what changed before it ships.

## What it changes for your team
- **Metrics and images on one page.** Each run starts with its metrics against the reference, then its images side by
  side. Nobody pastes screenshots in a chat thread to argue which version looks better.
- **Every commit, every chart, every light level.** CI runs the pipeline on your test set; the review starts with the
  runs whose images changed the most.
- **Down to the pixel, at any size.** Synced zoom, wipes, differences, and the values your code saved, 16-bit and
  float included, from thumbnails to a 113-megapixel test wall, and on videos frame by frame.
- **Bit-exact before silicon.** CI checks that a fixed-point model's outputs didn't change, file by file, before a
  change reaches the chip team.

## Try it on the demo {#run-this-example}
[`examples/image-quality`](https://github.com/Samsung/qaboard/tree/master/examples/image-quality) simulates the camera
of a fictional warehouse robot (lens blur, a Bayer sensor, noise), then runs an image pipeline on the raw image:
demosaic, denoise, sharpen, tone map. It measures PSNR and SSIM against the ideal output, noise, sharpness (MTF50),
halos (edge overshoot) and color errors (ΔE 2000). The `hw-model` platform runs the same pipeline in fixed-point
integers, like a camera chip.

<details>
<summary>The story the pictures tell: six weeks of commits</summary>

1. A new bilateral denoiser wins 1.6 dB of PSNR in low light and halves the noise. It's merged.
2. The images show halos along strong edges: the edge overshoot went from about 4% to 11%.
3. A clamp on the sharpening keeps the PSNR gain and brings the overshoot back to 5%.
4. On the fixed-point model, rounding changes are checked bit for bit before they reach the chip.

</details>

With a QA-Board server ([quickstart](/docs/get-started/quickstart)), from a clone of the repository:

```bash
cd examples/image-quality
pip install qaboard -r requirements.txt
qa run --input charts/slanted-edge.png       # one run
qa --share batch ci                          # 5 charts and 4 photos, at ISO 100 and 3200
qa --platform hw-model --share batch bitexact  # the fixed-point model
```

The first run downloads the photos and generates the test charts. Shared results go to `/mnt/qaboard`, or to
`$QA_STORAGE`. With the [quickstart](/docs/get-started/quickstart#save-results-from-your-computer)'s server, first
`export QABOARD_URL=http://localhost:5151 QA_STORAGE=/tmp/qaboard`. The example's
[README](https://github.com/Samsung/qaboard/tree/master/examples/image-quality#how-its-wired) explains each file.
