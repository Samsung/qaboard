For camera, ISP and imaging teams, and for embedded teams that hand an algorithm over to silicon. This page follows the
camera ISP example: what it computes, how the team uses QA-Board, and the configuration that does it.

## The problem
Image quality metrics disagree with eyes. PSNR goes up while edges get halos; noise goes down while texture turns to
plastic. A team needs the metrics on every commit, and the images themselves, next to the reference's, down to the
pixel, on charts and photos, in good and in low light. When the pipeline also runs on a chip, its fixed-point model
must match bit for bit, commit after commit.

## The example
[`examples/image-quality`](https://github.com/Samsung/qaboard/tree/master/examples/image-quality) simulates the camera
of a (fictional) warehouse robot: lens blur, a Bayer sensor, noise. It then runs the image pipeline on the raw image:
demosaic, denoise, sharpen, tone map. On test charts and photos, it measures PSNR and SSIM against the ideal output,
noise in flat patches, sharpness (MTF50), halos (edge overshoot) and color errors. The `hw-model` platform runs the same
pipeline in fixed-point integers, like the camera chip.

Its story, six weeks of commits replayed into QA-Board:
1. A new bilateral denoiser wins 1.6 dB of PSNR in low light, and halves the noise. It's merged.
2. The images show halos along strong edges: the edge overshoot went from about 4% to 11%.
3. A clamp on the sharpening keeps the PSNR gain and brings the overshoot back to 5%.
4. On the fixed-point model, rounding changes are checked bit for bit before they reach the chip.

## The configuration
*qaboard.yaml* says where the inputs are, which files to show and how, and which files must stay bit-accurate. Paths
with `:stage` give the synced slider over the stages.

<RepoFile path="examples/image-quality/qaboard.yaml" title="qaboard.yaml" section="inputs,outputs,bit_accuracy" />

Each metric has a label, a unit, a target, and whether smaller is better: the web app colors changes with them. The
last lines pick the metrics of the **Summary**, and those on each run's card and in the tables.

`qa/main.py` runs the camera simulation and the pipeline, writes the images and plots, and returns the metrics. See

file.

## Run this example
With a QA-Board server ([quickstart](/docs/get-started/quickstart)), from a clone of the repository:

```bash
cd examples/image-quality
pip install qaboard -r requirements.txt
qa run --input charts/slanted-edge.png       # one run
qa --share batch ci                          # 5 charts and 4 photos, at ISO 100 and 3200
qa --platform hw-model --share batch bitexact  # the fixed-point model
```

The first run downloads the photos and generates the test charts. Results go to `/mnt/qaboard`, or to `$QA_STORAGE`.
