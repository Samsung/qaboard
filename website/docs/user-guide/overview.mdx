QA-Board shows what each commit changed. Your team's CI runs every commit on the same test inputs. QA-Board puts the
results next to a reference's, like the last release: the metrics, and the outputs behind them, from images and videos
to plots and logs. You see whether the commit is better and where it differs, and you share a link to what you found.

This guide is for everyone who looks at results in the web app: image-quality and test engineers, integrators,
algorithm developers, team leads. You don't need to know how the project was set up.

## The words you need {#words}
| Word | What it means |
|---|---|
| **Commit** | A version of the code. QA-Board shows results commit by commit. |
| **Run** | The code of one commit, on one input (an image, a video, a recording...), with one configuration, like `low-light`. A run has output files, metrics and a log. |
| **Batch** | The runs of a commit that belong together. The one CI runs is shown as **CI**; tuning experiments and your own runs get their own batches. |
| **Metric** | A number each run reports: PSNR, mAP, p99 latency... Changes are green when they're better, red when they're worse. |
| **New and reference** | What you look at, and what it's compared with. By default, the reference is the latest results of the project's reference branch, often `main`. |
| **Milestone** | Results saved to compare with later: a release, a benchmark, your best tuning. Yours, or shared with the project. |

The other words, and how the `qa` command line and the server work together: [Key concepts](/docs/get-started/concepts).

Around it, the web app has three more pages: the **projects list**, its home page; a project's **commit list**; and
**History**, a metric over the commits of a branch. On every page:
- the **sidebar** has the project's pages, or the commit's views. Hover a view to see what it shows. The **?** button
  at the top, or the <kbd>?</kbd> key, opens a cheat sheet;
- the **top bar** has the commit list's dates and search box, or, on a commit page, the new and reference bars;
- on a commit page, the **View options** sit on the right. Press <kbd>o</kbd> to show or hide them.

<details>
<summary>Every part of the page</summary>

- **Left sidebar**:
  - The **QA-Board** title goes back to the projects list. Next to it, the **What's new** button opens the
    [release notes](/docs/user-guide/whats-new), the theme button switches between light, dark and your system's theme,
    and the **?** button opens the cheat sheet: shortcuts, QA-Board's words, and a link to this guide.
  - The project's avatar goes back to the project's commit list.
  - Menus that depend on the page: branch, code, History, integrations and milestones on the commit list; the
    [views of the commit page](/docs/user-guide/commit-page#views) on a commit page.
  - Your login, at the bottom, and **Collapse**, which shrinks the sidebar to a rail of icons (hover one for its name).
    <kbd>Ctrl</kbd> + <kbd>{'\\'}</kbd> (<kbd>⌘</kbd> + <kbd>{'\\'}</kbd> on macOS) collapses or expands it too; it
    remembers your choice.
- **Top bar**: on the commit list and History, the date range and a search or filter box. On a commit page, two bars:
  the **new** commit on top, the **reference** below. See [The top bars](/docs/user-guide/commit-page#the-top-bars).
- **View options**: on the commit page, a panel on the right to show or hide visualizations, pick which of their files
  to show, turn on viewers' options and sort runs. Click its icons when it's collapsed to a rail. It starts open when
  the window has room for it, then remembers your choice. It only shows on the views of the runs' results. See
  [View options](/docs/user-guide/commit-page#view-options).

The addresses of the pages, to type or share:

| Page | Address |
|---|---|
| Projects list | `/` |
| Commit list | `/<project>`, `/<project>/commits/<branch>`, `/<project>/committer/<name>` |
| Commit page | `/<project>/commit/<hash>` |
| History | `/<project>/history/<branch>` |

</details>
