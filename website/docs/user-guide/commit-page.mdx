A commit page shows the results of one commit, the **new** one, next to a **reference**: by default, the latest results
of your project's reference branch. It's where you answer "what did this commit change?". This page shows you around.

To review a commit, go from the big picture down to the pixels:

1. **Summary**: did the main metrics get better or worse? See [Reading metrics](/docs/user-guide/metrics).
2. **Metrics Diff**: which runs changed, and by how much?
3. **Visualizations**: look at those runs' outputs next to the reference's.

For a guided tour on the demo data, follow [Your first review](/docs/user-guide/first-review).

## The two bars {#the-top-bars}
The **new** bar, on top, holds the commit you look at; the **ref** bar, below, what you compare it with. They work the
same way. Each shows:

- the commit message, author and date;
- the **commit hash**: type another one to switch commits, or click **Change** to pick a branch, a milestone, or to
  switch new and reference. See [Picking a reference](/docs/user-guide/comparing-results#picking-a-reference);
- the **branch**: click it to select its latest commit;
- a **star**, to save the results you see (this batch, with its filter) as a
  [milestone](/docs/user-guide/milestones#saving-a-milestone);
- a **filter** box, to keep only some runs, and the counters of runs, running, pending and failed below it. See the
  [filter syntax](/docs/user-guide/finding-results#filter-syntax);
- the **batch selector**: the CI batch, your local runs, tuning experiments... See
  [Batches](/docs/user-guide/finding-results#batches);
- a refresh button, and a menu (☰) with the commit's and the batch's folders and actions.

The **Logs**, **Available Tests** and **Run Tests / Tuning** views only concern the new commit: they hide the
reference bar. While runs are pending, the page refreshes by itself every 15 seconds.

<details>
<summary>Every item of the ☰ menu</summary>

| Section | Items |
|---|---|
| Commit | **Copy artifacts directory** (Linux path, and Windows path when your server has path mappings), **View in browser**. |
| Batch | **Copy output directory**, **View in browser**. **Move runs to another batch**, **Rename batch**. |
| Redo | **Redo deleted runs**, **Redo failed runs**, **Redo all runs…**. With a filter, they redo only the runs that match it. See [Running from the web app](/docs/user-guide/running-from-the-webapp#redo-stop-and-clean-up-runs). |
| Delete | **Delete failed runs…**, **Delete all runs…**, **Delete multiple batches**. With **Delete files, keep metadata**, only the files are deleted, optionally only those matching patterns like `*.png`. |

Batches that are milestones are protected: delete the milestone first, or delete only their files or their failed runs.

</details>

<details>
<summary>The messages above the views</summary>

- **N running** / **N pending**: hover to list the runs. **Stop runs** cancels them.
- **N failed**: the failed runs, each name opens its log. **Open the logs** shows the [Logs](/docs/user-guide/logs)
  view.
- **N of the runs below were deleted**: **Redo deleted runs** runs them again.
- **Be careful, those are local runs**: they were started from someone's workspace, and may not match the committed
  code.
- **This commit's artifacts were deleted**, **are incomplete**, or **are being recreated**: when and by whom, and what's
  missing. **Recreate the artifacts** asks your CI to rebuild them, if the project
  [configured it](/docs/storage/deleting-old-data#recreating-artifacts). Otherwise, **Restore the artifacts** restores
  the files from the source code, but not build outputs like binaries.
- For batches started from the web app: **Your batch is waiting for LSF**, **The batch you started from QA-Board
  failed**... See [Batches started from QA-Board](/docs/user-guide/logs#started-from-qa-board).
- On the views that show runs, what all the runs share: see
  [Reading configurations](/docs/user-guide/comparing-results#reading-configurations).

</details>

## View options {#view-options}
The **View options** panel, on the right, changes what the views show, and in which order. Press <kbd>o</kbd> to show
or hide it. It lists only what applies to the view you're on:

- **Visualizations**: a switch per visualization, including the ones hidden by default.
- **Files to show**: when runs have several files for a visualization, like the stages of a pipeline or the frames of
  a sequence, which one every card shows. See
  [Pipeline stages and frames](/docs/user-guide/other-viewers#pipeline-stages-and-frames).
- **Viewers**: **Compare images** sets how every image viewer compares new and reference: side by side, with a wipe,
  one at a time, or their difference. Then the project's own switches, if it has some.
- **Configuration**: the settings all the runs shown share, and **Hide them in each run**.
- **Sort runs**: by name, run id, storage, a tuning parameter or a metric, for the tables and the run cards. Until you
  choose, runs are sorted by the project's default metric, marked *(default)*.

**Reset** goes back to the project's defaults, except for the sorting.

<details>
<summary>More about the panel</summary>

- **Collapsed**, it's a thin rail with an icon per section: hover an icon to see what the section is set to, click it
  to open the panel there. A dot on an icon means the section differs from the project's defaults.
- It starts open when the window has room for it and the results, else collapsed. Your choice is remembered.
- **Resize** it by dragging its left edge, or focus the edge and use the arrow keys. Double-click the edge for the
  default width. On narrow windows, the open panel covers the page: <kbd>Esc</kbd> closes it.
- The number next to its title counts what differs from the project's defaults: hover it for the list.
- **Visualizations**: the header counts how many are shown. Visualizations without files in these runs are listed
  apart. A search box appears when there are many.
- **Files to show**: until you pick a value, each run shows its own default (its last value when the values are
  numbers, like its last frame, else its first). The value you pick applies to all runs; a run without it shows the
  closest one, with a note on its card. **Per run** lets you choose in each card instead. Changing an option keeps the
  image viewers' zoom and region.
- **Compare images** can also be set above any image, or with the keys <kbd>1</kbd> to <kbd>4</kbd>.
- **Sort runs**: the order reads like the values: *Highest first*, *A to Z*, *Newest first*... It sorts by the new
  runs' values. The Summary doesn't use it.

</details>

## The views {#views}
The sidebar lists the views, grouped by what they're about. Each one answers a different question.

| View | Use it to... | |
|---|---|---|
| <a id="summary"></a>**Summary** | Get the big picture: how the main metrics changed | [Reading metrics](/docs/user-guide/metrics#summary) |
| <a id="metrics-table"></a>**Metrics Table** | Check each run's metrics against their targets | [Reading metrics](/docs/user-guide/metrics#metrics-table) |
| <a id="metrics-diff"></a>**Metrics Diff** | Find the runs that improved or regressed vs the reference | [Reading metrics](/docs/user-guide/metrics#metrics-diff) |
| **Visualizations** | Look at images, videos, plots, text... next to the reference | [Run cards](#run-cards), then the [image](/docs/user-guide/image-viewer), [video](/docs/user-guide/video-viewer) and [other viewers](/docs/user-guide/other-viewers) |
| **Output Files** | Browse and diff every file the runs created | [Output Files](#output-files) |
| <a id="logs"></a>**Logs** | Find out why a run failed, follow running runs | [Logs and failed runs](/docs/user-guide/logs) |
| **Artifacts & Configs** | Diff the build and configuration files with the reference commit | [Artifacts & Configs](#artifacts-and-configs) |
| **Code** | Open the commit on your git server | [Code](#code) |
| <a id="available-tests"></a>**Available Tests** | See, check and edit the batches of tests you can run | [Running from the web app](/docs/user-guide/running-from-the-webapp#available-tests) |
| <a id="run-tests--tuning"></a>**Run Tests / Tuning** | Run this commit's code on more tests, or with other parameters | [Running from the web app](/docs/user-guide/running-from-the-webapp#running-tests-and-tuning) |
| <a id="tuning-analysis"></a>**Tuning Analysis** | See how the metrics depend on tuning parameters, and the best ones | [Running from the web app](/docs/user-guide/running-from-the-webapp#tuning-analysis) |

The sidebar also has the project's **Integrations** (see
[Running from the web app](/docs/user-guide/running-from-the-webapp#integrations)) and its
[milestones](/docs/user-guide/milestones#finding-milestones). Hover a view's name for a reminder of what it shows.
Some projects open another view by default. The view you're on is part of the page's link: see
[Sharing](/docs/user-guide/sharing#whats-in-the-url).

## Run cards {#run-cards}
The **Visualizations** view has one card per run. A card starts with:

- **the run's name**, usually its input. Hover it for its batch, input path and database (click to copy), metadata,
  compute time, date and storage. Click it to see this input's results over time, in
  [History](/docs/user-guide/history-and-dashboards).
- **tags** for its platform and configuration, and how they differ from the reference run's: see
  [Reading configurations](/docs/user-guide/comparing-results#reading-configurations). Yellow **Input**, **Config** or
  **Platform** tags (with a `≠`) mean the reference run is not exactly the same: see
  [How runs are matched](/docs/user-guide/comparing-results#how-runs-are-matched).
- **its main metrics**, each with its change against the reference run, colored when it gets better or worse: see
  [what the colors mean](/docs/user-guide/metrics#colors).

Then come the visualizations the project configured, new next to reference. A file identical to the reference's is
tagged **Identical to the reference**. Cards load their files as you scroll to them.

Next to the run's name, the menu (☰) acts on the run. You need to be logged in.

<Shot
  id="commit/run-menu"
  caption="Each run card's menu redoes the run, or deletes it, or only its output files. While a run is pending or running, Mark as failed replaces Redo."
/>

The folder icon opens the run's output directory (or the reference's) in the [file browser](/docs/user-guide/files);
the copy icon copies its path, as a Linux or a Windows path. The button at the card's top right shows the card in full
screen.

To gather files from all the runs in one folder, use **Export**, next to the view's title: see
[Exporting files](/docs/user-guide/sharing#exporting-files).

## Output Files {#output-files}
Every file each run created, as a tree, compared with the reference run's files. Next to the view's title, the storage
the runs shown use.

<Shot
  id="commit/output-files"
  caption="Only the files that differ from the reference are listed: here, the pipeline stages that a rounding change touched. Click Help for what the icons mean."
/>

- By default, only the files that are **different, added or removed** are listed. **Show all files**, **Hide runs
  without files**, **Expand all folders**, **Color-blind friendly** and the path filter change that.
- **Click a file** to see its diff with the reference's. <kbd>Ctrl</kbd>-click or <kbd>Shift</kbd>-click to diff
  several. **Next diff** jumps to the next change.
- **Help** explains the icons and colors: bit-accurate, different, missing in the reference, only in the reference...

<Clip
  id="commit/bit-accuracy-diff"
  caption="Click a file to diff it in place: Next diff jumps to the register that changed. Ctrl-click another file to diff it too. On a commit that only changed docs, the run is Bit-accurate."
/>

When all the files your project checks are identical to the reference's, the run is tagged **Bit-accurate**. Files the
project doesn't check (`bit_accuracy.patterns` in *qaboard.yaml*) are grayed and tagged **not checked**, like
*metrics.json*, which has the run time. This is the view for [bit-accuracy tests](/docs/bit-accuracy).

<a id="artifacts--configs"></a>

## Artifacts & Configs {#artifacts-and-configs}
Compares the commit's [artifacts](/docs/storage/artifacts) with the reference commit's: the configuration files, the
build, and anything else the project saves with `qa save-artifacts`. Pick which artifacts to explore with the buttons
at the top.

<Shot
  id="commit/artifacts-configs"
  caption="Between two quantization commits, only build/flags.json changed: its diff shows which flags."
/>

It works like Output Files: only the differences are listed, click a file to diff it. The buttons at the bottom copy the
artifacts' path or open their folder. When a commit has no artifacts, the view says to run `qa save-artifacts`,
usually in your CI.

## Code {#code}
Opens the commit on your git server, in a new tab. Hover it for the commit's changes, its files (in a monorepo, the
project's folder), the branch's files and commits, and the repository.
