## Keyboard shortcuts

Press <kbd>?</kbd> anywhere in the web app (or click the **?** button in the sidebar) for a cheat sheet of these shortcuts, QA-Board's words and the filter syntax.

| Key | Where | What it does |
|---|---|---|
| <kbd>?</kbd> | Everywhere | Open or close the cheat sheet. |
| <kbd>t</kbd> | Text viewers | Swap **new** and **reference** in place, to flip between them. Applies to all viewers on the page. |
| <kbd>1</kbd>-<kbd>4</kbd>, <kbd>t</kbd>, <kbd>+</kbd> <kbd>-</kbd> <kbd>0</kbd> | Images (anywhere on the page: the viewer under the mouse, else the one used last) | Pick the [comparison mode](comparing-results.mdx#image-viewers) (side by side, wipe, single, difference), swap new and reference (one image shown: the other, then their difference), zoom. <kbd>p</kbd> shows or hides the pixel values, <kbd>h</kbd> starts a [blind test](comparing-results.mdx#blind-test) (then reveals and ends it), <kbd>f</kbd> goes full screen, <kbd>[</kbd> <kbd>]</kbd> go to the previous or next region of interest. |
| <kbd>o</kbd> | Commit page | Show or hide the [view options](commit-page.mdx#view-options): visualizations, files to show, viewers, sorting. |
| <kbd>Ctrl</kbd> / <kbd>Shift</kbd> + click | Output Files, Artifacts & Configs | Select several files to diff. |
| <kbd>Space</kbd>, <kbd>←</kbd> <kbd>→</kbd>, <kbd>&lt;</kbd> <kbd>&gt;</kbd> | Videos (hover or click a player) | Play or pause, previous or next frame (one second with <kbd>Shift</kbd>), slower or faster. <kbd>+</kbd> <kbd>-</kbd> <kbd>0</kbd> zoom, <kbd>1</kbd>-<kbd>4</kbd> pick the comparison mode, <kbd>t</kbd> toggles, <kbd>p</kbd> pixel values, <kbd>[</kbd> <kbd>]</kbd> regions, <kbd>n</kbd> <kbd>N</kbd> where the videos differ most, <kbd>h</kbd> blind test, <kbd>f</kbd> full screen, <kbd>m</kbd> mutes. |
| <kbd>Ctrl</kbd> / <kbd>⌘</kbd> + <kbd>S</kbd> | Available Tests | Save the batches file. |
| <kbd>Esc</kbd> | Dialogs, What's new | Close. |
| <kbd>Ctrl</kbd> / <kbd>⌘</kbd> + <kbd>{'\\'}</kbd> | Everywhere | Collapse or expand the sidebar. |
| ↑ ↓ <kbd>Enter</kbd> | Batch selector, filter suggestions | Pick an item without the mouse. |

Shortcuts are ignored while you type in a text box.

## Tricks worth knowing
- **Click a run's name** on a card to see the history of that input.
- **Hover almost anything**: metric names show their description, values show their exact number, `≠` tags explain reference mismatches, run names show metadata and paths to copy.
- **Full screen**: image viewers have a [full screen](comparing-results.mdx#full-screen) button (or <kbd>f</kbd>) to compare images on the whole screen, and each card has one at its top right.
- **Compare two batches of the same commit**: in the commit bar's **Change** menu, **Also select as reference**, then pick another batch in the reference bar.
- **Compare across projects**: **Change Project** in the same menu, e.g. to compare two sub-projects of a monorepo.
- **Sort by a metric** in the view options to see the worst regressions first.
- **Filter with negatives and regexps**: `-night`, `2X5|GW1`, `threshold:0.5`, `fail`. See the [filter syntax](finding-results.mdx#filter-syntax).
- **Search the batch selector**: type `failed`, `running`, `local`, `tuning` or a user name.
- **Short hashes** work everywhere you type a commit.
- **Copy an image** with the **Copy** button above image viewers, and paste it straight into a chat.
- **Share the exact view**: everything is in the URL, see [Sharing](sharing.mdx).

## FAQ

### I can't find my commit
- Widen the **date range** of the commit list: by default it only shows the last 3 days.
- Only commits **with results** are listed. If your CI didn't run QA-Board yet, the commit doesn't exist for QA-Board.
- Paste its hash in the **Filter...** box and choose **Go to commit**.
- Check you're in the right **project**: in a monorepo, each sub-project is a separate project.

### The page says "No results" or "Error"
- **No results**: the commit's CI batch has no finished runs. Check the CI pipeline, or pick another batch in the batch selector (the commit may only have tuning or local runs).
- An **Error** tag next to the commit: hover it. A `404` usually means a wrong commit hash, or runs saved in another project. A `500` is a server error: contact your QA-Board admins.

### Why is the reference not what I expected?
By default it's the latest commit with results on the project's reference branch, when you opened the page. Check the **ref** bar, and change it as explained in [Picking a reference](comparing-results.mdx#picking-a-reference). Also check the reference **batch** and **filter**.

### Some runs are compared with the wrong reference run
Look for yellow `≠` tags: the best match used another configuration, platform or tuning parameters. Make the reference filter match the new filter, or choose a reference batch with the same tests. See [How runs are matched](comparing-results.mdx#how-runs-are-matched).

### A run is stuck as pending
If it's really dead (e.g. killed by the cluster), use **Mark as failed** in the run's ☰ menu, then **Redo** it. See [Running from the web app](running-from-the-webapp.mdx).

### My local runs don't show up
Runs started from your workspace only appear in QA-Board with `qa --share`, see [QA CLI tips](../using-the-qa-cli.mdx). They show up in a batch named after you (`you 🏠 label`), with a warning that they may not match the committed code.

### Why does the "What's new" dialog show up again?
"Seen" release notes are remembered by your browser. A new browser, another computer or a private window doesn't know you've seen them. See [What's new](whats-new.mdx).

### Where are the files?
On a shared storage. Copy the paths from the ☰ menus, or see [Where is the data saved?](../storage/where-is-the-data-saved.mdx).

### I'd like a new feature, or I found a bug
Tell your QA-Board admins, with the URL of the page. See [Sharing](sharing.mdx#bug-reports-and-support).
