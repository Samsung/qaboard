Show a colleague what you see, give them the path to the files, or gather the images for a report.

## Copy the page's link {#links-are-shareable}
Most of what you select is saved in the page's link. **Copy it from your browser's address bar** and send it: whoever
opens it sees the same commits, reference, batches, filters and view as you, with the images compared the same way.
The browser's back and forward buttons work too.

The link doesn't keep the viewers' zoom. To point at a spot, paste a copy of the image too (the copy button above the
images, see [Copy and save](/docs/user-guide/image-viewer#copy-and-save)), or name the region, e.g. *Window frame
(halos)*.

The reference commit is written in the link as soon as it's known. A link shared today still shows the same comparison
next month, even after the reference branch moved on.

:::tip
To share a [milestone](/docs/user-guide/milestones), copy its link from the milestones menus or its dialog: it keeps
working when the milestone is renamed. See [Links to milestones](/docs/user-guide/milestones#links-to-milestones).
:::

### What's in the link {#whats-in-the-url}
On a commit page, the link holds the new commit, the reference, their batches, filters and names, the view, how runs
are sorted, and the view options: the visualizations shown, the files to show, and how images are compared. On the
commit list, it holds the search and the dates; on the History page, the filter, the batch and the chart options.

Options left at their default are left out, to keep links short: e.g. the `default` batch, an empty filter, the
project's default metrics and view, or visualizations shown by default. Links follow the project's defaults.

Some things are yours, not the link's: your pinned projects, the groups of milestones you collapsed and the pixel
values you show follow your account when you're signed in; whether the view options are open and how wide, and the
statuses of the CI jobs you started, stay in your browser. The viewers' zoom, the regions you picked and the display
adjustments are not saved at all.

<details>
<summary>Every parameter of the URL</summary>

On a commit page, `/<project>/commit/<hash>?...`:

| Parameter | What it holds |
|---|---|
| path `/<project>/commit/<hash>` | The project and the **new** commit |
| `reference` | The **reference** commit |
| `batch`, `batch_ref` | The new and reference batches (`default` is CI) |
| `filter`, `filter_ref` | The new and reference [filters](/docs/user-guide/finding-results#filter-syntax) |
| `label`, `label_ref` | The [names you gave](/docs/user-guide/comparing-results#naming-what-you-compare) the new and the reference results |
| `compare`, `ref_index` | The [other references](/docs/user-guide/comparing-results#several-references) you stacked, and which one is shown |
| `new_project`, `ref_project` | Only when results come from [another project](/docs/user-guide/comparing-results#picking-a-reference) |
| `selected_views` | The view: `summary`, `table-kpi` (Metrics Table), `table-compare` (Metrics Diff), `output-list` (Visualizations), `bit_accuracy` (Output Files), `logs`, `parameters` (Artifacts & Configs), `groups` (Available Tests), `tuning` (Run Tests / Tuning), `optimization` (Tuning Analysis) |
| `sort_by`, `sort_order` | How runs are sorted |
| `controls` | Visualizations shown or hidden, how images are compared, the files to show (as JSON, only what you changed) |
| `show_all_files`, `expand_all`, `files_filter`... | Options of the Output Files view (`params_...` for Artifacts & Configs) |

On the commit list, the search box is saved as `search`, and the date range as `from` and `to` (e.g.
`?from=2026-09-01&to=2026-09-30`). On the History page, the filter, batch and chart options (`selected_metric`,
`breakdown_per_test`, `relative`...) are saved too.

</details>

## Copy a path, a hash or an image {#copying-paths-hashes-and-images}
Results live on a shared storage, so you often want a path rather than a link:

- **A run's output folder**: the copy and folder icons on each run's card, for the new and the reference run. The
  folder icon opens it in the [file browser](/docs/user-guide/files), where you can copy the path of any file.
- **A commit's or a batch's folder**: the ☰ menu of a commit row or of a commit bar, as a **Windows** or **Linux**
  path, or open it in the browser.
- **The commit hash**: the copy icon next to the hash, in the commit list.
- **An input's path, database or batch**: hover the run's name on its card and click the value to copy it.
- **A configuration**: hover a configuration tag, copy it as JSON, or in tuning format to paste in a
  [tuning experiment](/docs/user-guide/running-from-the-webapp#running-tests-and-tuning).
- **An image**: the copy button of an image viewer copies the new image, the reference or their difference to your
  clipboard, ready to paste in a chat or a slide, or saves it as PNG. See
  [Copy and save images](/docs/user-guide/image-viewer#copy-and-save).

## Export files for a report {#exporting-files}
To put the outputs of many runs in a slide deck or a script, gather them in one folder. In the **Visualizations** and
**Output Files** views, **Export** collects the files matching a pattern from all the (filtered) runs, new and
reference:

1. Filter the runs you want, e.g. `low-light` (see [Filter the runs](/docs/user-guide/finding-results#filter-syntax)).
2. Click **Export** at the right of the view's title.
3. Type a pattern, like `*.png`, `*.txt` or `**/*.jpg` (`**/` matches any number of folders).
4. Click **Export** in the box, or press <kbd>Enter</kbd>. The export folder's Windows path is copied to your
   clipboard, and both its Windows and Linux paths show in the box. They stay there if you close the box and open it
   again.
5. Open the folder to share or post-process the files.

By default, the exported files are **links** to the original files, in a shared folder: nothing is copied, so it's
fast. Use **Edit where** to choose your own folder: files are then copied (or linked, if it's on the same filesystem).
In a folder that existed before, QA-Board only adds files: it never replaces what's there (the box lists the files
it skipped), and the folder isn't listed with your exports in **Storage usage**.

## Report a bug or ask for help {#bug-reports-and-support}
- If the web app crashes, you'll see **Sorry, something went wrong!** with a **Report the bug** button. It opens an
  email with the page's link and the error filled in, or your team's issue tracker: your admins choose where bug
  reports go.
- For anything else, send the link of the page you're looking at to your QA-Board admins: with it, they see what you
  see.
- Questions on how a project's results are produced (metrics, visualizations, inputs) go to that project's lead.
