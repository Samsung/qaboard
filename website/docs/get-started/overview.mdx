QA-Board puts every commit's outputs and metrics next to a reference's, so your team sees what changed and agrees
it's better. The docs have one section per job. Pick the one that matches what you want to do.

## I want to look at results my team produced {/* #look-at-results */}
Your team already sends results to QA-Board, and you have a link to its web app. You don't need to install anything
or know how the project was set up. Read the **[user guide](/docs/user-guide/overview)**: find a commit, read its
metrics against the reference, compare images and videos, follow a metric over time, start runs and tuning from the
browser.

## I want to try QA-Board {/* #try-it */}
Start a server on your computer with demo projects, then save the results of an example project to it. It takes a
few commands, with Docker Compose or a kind cluster.

## I want to send my project's results {/* #integrate-a-project */}
You wrap your code with `qa`, the command line, and describe your project in *qaboard.yaml*. The integration decides
what the web app shows for your project: your metrics with their targets, your output files in the right viewers
(images, videos, plots, point clouds, flame graphs, test reports), batches on your cluster or in CI, tuning from the
browser, and a quality gate (experimental). Each step takes minutes and shows something new.
Read **[Project integration](/docs/introduction)**.

## I run the server for my team {/* #run-a-server */}
Set up QA-Board on your machines with Docker Compose or Kubernetes, then add single sign-on, project roles, backups
and monitoring when you need them. Read the **[Admin](/docs/deploy)** section.
