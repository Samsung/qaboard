Inputs are what your code runs on: an image, a video, a recording, a load profile, a folder of files. `qa` finds them
as paths, relative to a folder you set in *qaboard.yaml*: the **database**. This page sets it up, so that
`qa run --input` and `qa batch` find your inputs.

## Set where your inputs are {#the-database}
The camera ISP example keeps its inputs in the project, in its `inputs/` folder:

<RepoFile path="examples/image-quality/qaboard.yaml" title="qaboard.yaml" section="inputs" />

Inputs are then paths relative to that folder:

```bash
qa run --input charts/slanted-edge.png
#=> runs on inputs/charts/slanted-edge.png
```

- `database` is relative to the project's root, where *qaboard.yaml* is, or absolute, e.g. `/mnt/datasets`. Give a
  `linux` and a `windows` path when the folder is mounted at different places. Without `database`, it's `/`.
- `{project}`, `{subproject}` and environment variables like `$DATASETS` are replaced in it.
- An absolute input path works too: `qa run --input /mnt/datasets/images/A.jpg`.
- `qa --database <folder> run ...` uses another database for one command.

## Recognize inputs inside folders {#identifying-inputs}
To run on every image of a folder, `qa` must know what an input looks like. Give it
[glob patterns](https://docs.python.org/3/library/glob.html) in `inputs.globs`: above, the camera ISP's inputs are
the PNG and TIFF images, and the YAML files that describe its videos. Batches can then list folders and wildcards, and
`qa` finds the inputs in them, in subfolders too:

```yaml title="qa/batches.yaml"
my-photos:
  inputs:
  - photos             # every input under inputs/photos
  - charts/*.png
```

When each input is a folder, recognize it by a file it contains, and set `use_parent_folder`. In the detector
example, each slice of the test set is a folder with its images and a *labels.json*:

<RepoFile path="examples/detection-eval/qaboard.yaml" title="qaboard.yaml" lines="9-15" />

```bash
qa run --input slices/indoor
```

:::tip
To see which inputs a batch finds, before running anything: `qa batch <batch> --list-inputs`. Inputs are sorted by
path, so a batch runs them in the same order on every machine.
:::

## Inputs in the example projects {#examples}
Each example project in the repository shows a kind of input, with its configurations and metrics:

| Project | An input | Configurations | Metrics |
|---|---|---|---|
| [Camera ISP](/docs/use-cases/image-quality) | An image: a test chart, a photo, the 113 MP test wall | The ISO: `base`, `low-light`, `night` | PSNR, SSIM, MTF50, edge overshoot, ΔE 2000 |

Batches list these inputs with their configurations, to run them together: see

## Several types of inputs {#advanced-handling-multiple-input-types}
Some projects have inputs of different kinds, recognized and processed differently, e.g. images and movies stored as
folders of frames. Give each type its settings under `inputs.types`:

```yaml title="qaboard.yaml" {3-11}
inputs:
  types:
    default: image
    image:
      globs: '*.raw'
    movie:
      globs: frame_000.jpg
      use_parent_folder: true
      database:                # the settings of inputs can change per type
        linux: /mnt/movies
        windows: F://movies
```

Choose the type of a batch with `type`, or on the command line with `qa --type`:

```yaml title="qa/batches.yaml" {6}
my-images:
  inputs:
  - my/image.raw

my-movies:
  type: movie
  inputs:
  - folder/of/movies
```

```bash
qa batch my-images                       # images, the default type
qa --type movie run --input folder/of/movies/A
```

`run()` gets the type in `context.type`:

```python title="qa/main.py"
def run(context):
    if context.type == "image":
        ...
    elif context.type == "movie":
        ...
```

A type can also have its own runner settings, e.g. another LSF queue for movies. They apply after those of
*qaboard.yaml*, and before the batch's: see [runner settings](/docs/batches-running-on-multiple-inputs#runner-settings-per-batch).

```yaml title="qaboard.yaml"
inputs:
  types:
    movie:
      runners:
        lsf:
          queue: <your-long-queue>
```
