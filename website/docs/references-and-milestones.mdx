Every result in QA-Board is compared with a reference: the web app shows each run next to the matching run of the
reference, and `qa gate` and `qa check-bit-accuracy` fail on the differences. As whoever integrates a project, you
choose the default reference, and the versions worth comparing with. People [pick other references](/docs/user-guide/comparing-results#picking-a-reference)
and [save milestones](/docs/user-guide/milestones#saving-a-milestone) in the web app.

## Set the default reference {#comparing-versus-a-reference}
By default, a commit is compared with the latest commit of the project's reference branch that has successful runs:

```yaml title="qaboard.yaml"
project:
  reference_branch: main
```

Run your CI on that branch (see [CI integration](/docs/ci-integration)): its latest results are what every other
commit is compared with. On a commit page, the reference's **Change** menu offers the reference branch, the
milestones, and to switch the new and reference commits:

<Shot
  id="commit/change-menu"
  caption="The reference's Change menu: the reference branch, main, then the shared milestones, kd-1.3 and kd-1.2."
/>

:::caution
Set `reference_branch`: without it, the commit page compares with the latest commit that has results on any branch,
while the **Change** menu, `qa check-bit-accuracy` and `qa gate` use `master`.
:::

## List reference branches in *qaboard.yaml* {#project-references}
Release branches and long-lived branches you often compare with can be listed under `project.milestones`:

```yaml {3-5} title="qaboard.yaml"
project:
  reference_branch: main
  milestones:
    - release/kd-1.3
    - quant/int8
```

They are listed in the **Milestones** menus under "From qaboard.yaml": picking one compares with the latest commit of
that branch. To keep the results of one commit, save a milestone instead.

## Use milestones in the CI and in scripts {#milestones}
Milestones are results saved in the web app to compare with later: a commit's batch, with a name like `kd-1.2`, notes,
and a filter. They're shared with everyone on the project, or private. See
[Milestones](/docs/user-guide/milestones) in the user guide for how people save and find them.

<Shot
  id="commits/milestones-menu"
  caption="The Milestones menu: the detector's releases, kd-1.3 and kd-1.2, shared with everyone, then a private milestone."
/>

For integrators:
- **Gate on a release:** `qa gate --reference kd-1.2`, or `gate.reference: kd-1.2` in *qaboard.yaml*, compares with a
  shared milestone, by its name (see [Quality gate](/docs/quality-gate#set-the-rules)). `#12` names the milestone
  whose link is `/<project>/milestone/12-...`, shared or not.
- **Read them from scripts:** `GET /api/v1/milestones?project=<project>` lists the shared milestones (and yours, with
  your [API token](/docs/apis#authentication)): each with its `label`, `group`, `notes`, `commit`, `batch` and
  `filter`.
- **Link to them:** each milestone has a link, `/<project>/milestone/<id>-<name>`, that anyone who can see the
  project can open. Renaming a milestone keeps its link.
- **Keep their results:** the [cleanup of old results](/docs/storage/deleting-old-data) keeps the batches that are
  milestones, and the web app won't delete all their runs.

`qa check-bit-accuracy --reference` takes a branch, a tag or a commit, not a milestone (see
[Bit accuracy](/docs/bit-accuracy#which-reference)).
