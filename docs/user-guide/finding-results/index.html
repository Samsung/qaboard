Finding results

Find the results you came for: your commit, the right batch of runs, then only the runs that matter.

Find your commit​

Open your project from the home page: you land on its commit list, the latest commits with results on all branches, newest first. From there, find a commit in one of three ways:

  • Scroll the list. Commits are grouped by day. On the right of each row, the N runs button (e.g. 5 runs) opens the commit page.
  • Search for it. Type a word of its message, a committer's name or the start of its hash in the search box at the top right (Search commits, or go to a branch or commit…). It searches all the project's commits, not only the latest. See Search commits.
  • Open its branch. Click the branch name in any row, or the reference branch at the top of the sidebar, to see only that branch's commits.
tip

The list shows the last 3 days. If your commit isn't there, search for it, or pick earlier dates at the top left.

Pick a project​

The home page lists every project with results: those you pinned first, then the ones that ran most recently.

  • Find one with the Filter projects... box. It looks at all projects, even those not shown yet: the list shows 50 at first, more as you scroll down (or click Show more).
  • Pin one on top of the list with its star. Pins are remembered by your browser only.
  • Source opens the project's git repository.

Click a project to open its commit list.

Project names are git paths, like group/repo. In a monorepo, each sub-project has its own entry, like group/repo/sub-project: if you can't find your results, check you're in the right one.

Read the commit list​

Each row is a commit: its message, short hash, branch, and when and by whom it was committed. On the right, how its CI batch went:

  • the project's main metric over the batch's runs, median and average. Hover … for all the aggregated metrics;
  • N failed in red, or N running and N pending while the CI batch runs;
  • N other batches: hover it to list the commit's tuning experiments and local runs, and open one;
  • N runs, which opens the commit page.

Waiting for results means the CI may still be running. No results means no run was uploaded for the commit's CI batch: check its CI pipeline, or open one of its other batches.

The list refreshes every minute. The 50 latest commits show up first, more come as you scroll down (or click More commits).

The compact list: one line per commit

To see more commits at once, pick Compact above the list (Comfortable brings back the rows above). Each commit then takes one line, in columns that line up like a table: an icon for the CI batch's status (finished, failed, running, waiting), the short hash, the message, the branch, the committer, the date, then the batch's results and the ☰ menu. The web app remembers your choice in this browser.

Hover to see what doesn't fit:

  • the message shows the whole commit message, the date the exact time;
  • the status icon counts the finished, failed and running runs;
  • the main metric's average shows its median and all the aggregated metrics;
  • +N batches lists the commit's other batches, like N other batches above.

The copy icon for the full hash shows up when you hover a row, or reach it with the keyboard.

Change the dates​

By default, the list shows the last 3 days. Pick other dates at the top left (the picker has shortcuts like "Past week"), and click the refresh button next to them to check for new commits.

  • At the end of the list, Older commits looks 7 more days back.
  • When no commit has results in the range, Search 7 more days does the same.
  • Searches ignore the dates: they look at all the commits.

Follow a branch or a committer​

  • A branch: click its name in a commit row, or the reference branch at the top of the sidebar. The page is /<project>/commits/<branch>.
  • A committer: click an avatar or a committer's name to see their commits on all branches: /<project>/committer/<name>.

A branch's page starts with a chart of the main metric over its commits: for each commit, the median (or average) over its runs, one line per batch (CI, nightly...). Pick the metric and the aggregation above the chart: sum adds up counts over the runs, like the number of tests of all the test suites. Hover a point to see its commit and the commit before it, click a point to keep it as the reference. To follow each test on its own, use History.

On a branch page, all the branch's commits in the date range come at once (up to 1000), for the chart.

Search commits​

The search box at the top right of the commit list (Search commits, or go to a branch or commit…) searches all the project's commits, not only those in the date range. On a branch page, it searches the branch's commits. Results come as you pause typing, newest first, under a "Searching all commits" banner that counts the matches.

You typeYou find commits...
cachewhose message, committer, branch or batch labels contain "cache"
3fa2c1the same, or whose hash starts with it
cache -agentthat contain "cache" but not "agent"
branch:perf, committer:kaitowhose branch contains "perf", by a committer whose name contains "kaito"

When your search could be a branch name (a single word, or a branch: term), the box also suggests the most recently active branches whose name contains it: pick one to open it.

More search syntax
You typeYou find commits...
cache shardmatching both words
"result cache"containing these words together
author:kaitolike committer:kaito
batch:tune or label:tunewith a batch whose label contains "tune"
message:p99 or msg:p99whose message contains "p99"
id:3fa2, commit:3fa2 or sha:3fa2whose hash starts with "3fa2"

A word matches the start of hashes when it has 4 or more hexadecimal characters. Searches are case-insensitive, and qualifiers can be excluded too (-branch:release). Unlike the filters of the commit page, they don't use regular expressions. The search is saved in the page's link, so a shared link shows the same results.

Go to a commit by its hash​

  • Type or paste a commit hash in the search box, then choose Go to commit: ....
  • Or edit the page's link: /<project>/commit/<hash>. Short hashes work.
  • On a commit page, you can also type a hash in the commit field of the new or reference bar (see choose another reference).

Open a milestone​

Releases and other results saved to compare with are in the sidebar's Milestones menu: see Finding milestones.

Pick a batch​

A commit can have several batches of runs: the CI's, your local runs, tuning experiments. On the commit page, the batch selector next to the filter box shows the selected batch: click it to pick another one.

  • CI is the batch from your continuous integration (label default).
  • user 🏠 label are local runs started by user from their workspace. A warning reminds you they may not use the code under version control.
  • Other labels are tuning experiments, or runs started with qa --label.

The new and reference bars each have their own batch selector, so you can compare a tuning batch with the CI batch of another commit.

Reading and searching the batch selector
  • Each entry shows how many of its runs finished out of the total (18/18 and a check mark), then those that failed (red cross) and are running (walking figure), the iteration of an automated tuning, a star for milestones, and who started it.
  • The list is searchable: type a label, a user name, or words like failed, running, local, ci, tuning.
  • The list opens on the selected batch, which has a check mark. Use ↑ ↓ and Enter to pick another one.

Filter the runs​

The filter boxes of the commit page's bars (Filter runs… for the new commit, Filter the reference's runs… for the reference) keep only the runs that match. The counters under them (8 runs, 4 failed...) count what's left, and the ? icon in the box recalls the syntax.

You typeYou keep runs...
low-lightwhose input path, configuration, platform, metadata, tuning parameters or batch contain "low-light"
low-light facadematching both words
-gradientnot matching "gradient"
facade|foliagematching either word
denoise_strength:1.6with the tuning parameter denoise_strength equal to 1.6 (also denoise_strength=1.6)
fail or crashthat failed
pending or runningthat are not finished
status:successthat succeeded (not failed, pending or running). -status:success keeps the others
id:1234with this run id

Filters are case-insensitive and are saved in the page's link, so a shared link shows the same runs. History has the same filter box.

tip

Each word of the filter is a regular expression: photos/(facade|foliage) keeps the runs of those two photos.
