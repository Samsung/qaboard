Finding results

Projects list​

The home page lists all projects that have results.

  • Search with the filter projects... box. It looks at all projects, even those not shown yet.
  • Pin a project at the top of the list with its star. Favorites are remembered by your browser only.
  • Projects are sorted by favorites first, then by their latest run. Each card shows when the last run (or commit) happened and how many commits have results.
  • The first 50 projects show up first, more come as you scroll down (or click Show more).
  • Source opens the project's git repository.

Click a project to open its commit list.

tip

Project names are git paths, like group/repo. In monorepos, each sub-project has its own entry, like group/repo/sub-project.

Commit list​

The project's home page lists the latest commits with results, grouped by day ("Today — 3 commits"). It refreshes every minute. The 50 latest commits show up first, more come as you scroll down (or click More commits). On a branch page, all the branch's commits in the date range come at once (up to 1000), for the metrics chart. At the end of the date range, Older commits looks 7 more days back.

Each commit row shows:

note

No results or Check the pipeline status... means the commit has no finished runs yet in its CI batch: check your CI pipeline.

Compact list​

To see more commits at once, pick Compact above the list (Comfortable brings back the rows above). Each commit then takes one line, in columns that line up like a table: an icon for the CI batch's status (finished, failed, running, waiting), the short hash, the message, the branch, the committer, the date, then the batch's results and the ☰ menu. The web app remembers your choice in this browser.

Hover to see what doesn't fit:

  • the message shows the whole commit message, the date the exact time;
  • the status icon counts the finished, failed and running runs;
  • the main metric's average shows its median and all the aggregated metrics;
  • +N batches lists the commit's other batches, like N other batches above.

The copy icon for the full hash shows up when you hover a row, or reach it with the keyboard.

Branches and committers​

  • The sidebar shows the project's reference branch: click it to see only its commits.
  • Click any branch name in a commit row to see that branch. The URL is /<project>/commits/<branch>.
  • On a branch page, a chart of a main metric over time comes first: for each commit, the median (or average) over its runs, one line per batch (CI, nightly...). Pick the metric and the aggregation above the chart. Hover a point to see the commit and its reference, click to freeze the reference. For more, use History.
  • Click an avatar or a committer name to see their commits, on all branches: /<project>/committer/<name>.

Searching commits​

The Filter... box at the top right searches all the project's commits, not only those in the date range (on a branch page, all the branch's commits). Results come as you pause typing, newest first, with a "Searching all commits" banner that counts the matches. When your search could be a branch name (a single word, or a branch: term), it also suggests the most recently active branches whose name contains it: pick one to open it.

You typeYou find commits...
denoisewhose message, committer, branch or batch labels contain "denoise"
3fa2c1the same, or whose hash starts with it, for words of 4 or more hexadecimal characters
denoise crashmatching both words
-wipnot matching "wip"
"fix the crash"containing these words together
branch:featurewhose branch contains "feature"
committer:alice or author:aliceby a committer whose name contains "alice"
batch:tuning or label:tuningwith a batch whose label contains "tuning"
message:speed or msg:speedwhose message contains "speed"
id:3fa2, commit:3fa2 or sha:3fa2whose hash starts with "3fa2"

Searches are case-insensitive, and qualifiers can be excluded too (-branch:release). Unlike the filters of the commit page, they don't use regular expressions. The search is saved in the URL (search=), so a shared link shows the same results.

Date range​

By default, the list shows the last 3 days. Change the range with the date picker at the top left (it has shortcuts like "past week"), and use the refresh button to reload.

tip

"Could not find a commit with results" usually means you should widen the date range.

Going to a commit by its hash​

  • Type or paste a commit hash in the Filter... box, then choose Go to commit: ....
  • Or edit the URL: /<project>/commit/<hash>. Short hashes work.
  • On a commit page, you can also type a hash in the commit field of the new or reference bar (see Comparing results).

Milestones​

The sidebar's Milestones menu lists the project's milestones: those from qaboard.yaml, the shared ones, and your private ones. Pick one to open it. See Milestones.

Batches​

A commit can have many batches. On the commit page, the batch selector next to the filter box shows the selected batch and lets you switch:

  • CI is the batch from your continuous integration (label default).
  • user 🏠 label are local runs started by user from their workspace. A warning reminds you they may not use the code under version control.
  • Other labels are tuning experiments or runs started with qa --label.
  • Each entry shows successful/total ✅, failed ❌, running 🏃, optimization iterations 🔁, a ⭐ for milestones, and who started it.
  • The list is searchable: type a label, a user name, or words like failed, running, local, ci, tuning.
  • The list opens on the selected batch, which has a check mark. Use ↑ ↓ and Enter to pick another one.

The new and reference bars each have their own batch selector, so you can compare a tuning batch with the CI batch of another commit.

Filter syntax​

The filter boxes of the commit page's bars (Filter runs… for the new commit, Filter the reference's runs… for the reference) keep only matching runs. The counters below them (8 runs, 4 failed...) count what's left.

You typeYou keep runs...
nightwhose input path, configuration, platform, metadata, tuning parameters or batch contain "night"
night indoormatching both words
-nightnot matching "night"
2X5|GW1matching a regular expression
threshold:0.5with tuning parameter threshold equal to 0.5 (also threshold=0.5)
fail or crashthat failed
pending or runningthat are not finished
id:1234with this run id

Filters are case-insensitive and are saved in the URL (filter= and filter_ref=), so a shared link shows the same runs.
