QA-Board for users

This guide is for the engineers who use the QA-Board web app every day to look at results: check what a commit changed, compare it to a reference, dig into images and logs, start a few extra runs, and share what they found.

You don't need to know how the project was set up to use it.

Other audiences
  • Project integration: to add QA-Board to a project (qaboard.yaml, inputs, metrics, visualizations, runners), start at Project Setup.
  • Admins who run the QA-Board server: see Server Bringup and the deployment runbook.

Key concepts in plain words​

ConceptWhat it means for you
ProjectUsually a git repository, sometimes a sub-folder of one (e.g. group/repo/sub-project). The projects list is the home page.
CommitA version of the code. QA-Board shows results per commit: the commit page is where you spend most of your time.
BatchA group of runs for a commit, with a label. The CI batch (label default) is shown as CI. Tuning experiments and your own local runs get their own batches.
Run (or output)The code from a commit, executed on one input, with one configuration, on one platform. Each run has its output files, metrics and logs.
InputWhat a run works on: an image, a movie, a recording, a test case... Inputs are identified by their path.
ConfigurationThe settings a run used (e.g. base, low-light), plus optional tuning parameters shown as key: value tags.
MetricsNumbers computed by each run (error, speed, quality...). The project's configuration decides which ones matter, their target and whether smaller is better.
New vs referenceResults are always shown for a new commit compared with a reference (ref). By default the reference is the latest commit with results on the project's reference branch.
MilestoneA commit (and batch) bookmarked as a reference: a release, a benchmark, "the version before my refactor". Some are shared with everyone, some are private to you.
ArtifactsFiles saved per commit, like the build output and the configuration files, so runs can be redone and configs compared.

Anatomy of a page​

  • Left sidebar:
    • The QA-Board title goes back to the projects list. Next to it, the What's new button opens the release notes, and the i icon opens this guide.
    • Your login, then the project's avatar: click it to go back to the project's commit list.
    • Menus that depend on the page: branch, code, history, integrations and milestones on the commit list; the views of the commit page on a commit page.
  • Top bar: on the commit list, the date range and a filter box. On a commit page, two bars: the new commit on top, the reference below.
  • Controls panel: on the commit page, a panel on the right edge to toggle visualizations, sync options between runs, and sort runs. Click the dark tab on the right edge to show or hide it.
