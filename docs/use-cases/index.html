The regressions QA-Board catches

Tests tell you it runs. QA-Board shows you it's better.

Every team that measures quality hits the same wall. The tests pass, the average moves a little, and the regression that matters is in one image, one slice of the test set, one percentile, one task. QA-Board runs every change on your test set, whether a person or a coding agent wrote it, and puts its outputs and metrics next to the reference's. The team sees what changed, and agrees it's better before it ships.

It's been Samsung's central quality platform since 2018: about 50 projects, more than 40 million runs.

The metric improved, the image got worse​

Camera, ISP, imaging. A new denoiser wins PSNR and adds halos. Synced zoom and image differences down to the pixel, a 113 MP test wall, every stage of the pipeline, bit-exact checks before silicon.

Smaller model, people missing​

Computer vision, ML. An int8 detector is 72% smaller and loses 35% of its mAP indoors. Metrics per slice and class, PR curves over the release model's, detections on the images, tuning to win it back.

Less CPU, and seconds of tail latency​

Performance engineering. A coding agent's cache saves CPU and halves capacity. Latency distributions under the same load on every commit, flame graph diffs, History, a gate on p99.

The robot thinks it's somewhere else​

Robotics, perception. A false loop closure pulls the trajectory meters away. 6DoF trajectories against the ground truth, maps in 3D, sensor videos in sync with the reference's.

The assistant stopped asking before acting​

LLM agents. Shorter tool descriptions, and an assistant reboots robots without confirmation. Each task against the reference, transcripts diffed, a report per task, a gate on unsafe actions.

Green CI, half the tests gone​

Software quality. Asked to fix CI, a coding agent deletes the failing tests. Test counts, flaky tests and coverage over time, each suite's tests against the reference's, a gate on deleted tests.

What every team gets​

The same review loop, whatever you measure:

  • Every commit against a reference: the reference branch, or a release saved as a milestone. Metrics first, green when they got better and red when they got worse, then the outputs behind them.
  • Viewers built for heavy data: images and videos synced down to the pixel, point clouds, trajectories, flame graphs, plots, test reports, logs, and the HTML reports your code writes.
  • History to find the commit that changed a metric, input by input.
  • Tuning from the browser: sweeps and automated tuning, run on the server, Celery or LSF, with an analysis of what matters.
  • A quality gate in CI, qa gate: experimental, it may change.
  • People and coding agents on the same results: agents run the same tests and read the same Metrics Diff; a person decides what ships. See coding agents.
  • Your compute, your storage, your network: qa runs where your code already runs (a laptop, CI, LSF, Celery, Dask, Jenkins), outputs stay on your storage, and the server is self-hosted, open source (Apache 2.0).
