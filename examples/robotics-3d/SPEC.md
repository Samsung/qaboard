# robotics-3d: odometry and mapping (`kitefin/slam`)

## Purpose
- **Shows:** QA-Board on robotics data: 6DoF trajectories against ground truth, point clouds, camera videos played in
  sync with the reference, error over time, and History on a trajectory metric.
- **Audience:** robotics, perception and automotive engineers.
- **Phase 3.**

## What the code computes
Python (numpy, scipy; ffmpeg for videos). Everything is simulated, so the ground truth is exact.

- **World:** a procedural warehouse per sequence: shelves, pallets, pillars and walls as boxes, from the sequence seed.
- **Robot and sensors:** a K3 drives a trajectory (splines with speed profiles). Depth camera 160x120 at 15 fps, 70°
  horizontal field of view, ray-cast against the boxes, noise σ = 1% of depth, dropouts at depth edges. IMU at 200 Hz,
  gyro and accelerometer noise with a bias random walk.
- **Odometry:** voxel downsampling, point-to-plane ICP from each frame to the last keyframe (`scipy.spatial.cKDTree`),
  started from the IMU's prediction. A new keyframe after `keyframe_dist` meters or `keyframe_angle` degrees.
- **Loop closure** (flag): keyframe descriptors (a coarse occupancy signature), candidate matches verified by ICP, then a
  pose graph solved with `scipy.optimize.least_squares`.
- **Evaluation:** ATE RMSE after SE(3) alignment, RPE (translation %, rotation °/m), drift at the end, loop closures,
  time per frame.

**Flags** (`build/flags.json`; defaults are the head of `main` at T0):

| Flag | Values | Default |
|---|---|---|
| `voxel_size` | meters | `0.05` |
| `icp_iterations` | 5-50 | `20` |
| `keyframe_dist`, `keyframe_angle` | meters, degrees | `0.3`, `10` |
| `imu_weight` | 0-1 | `0.6` |
| `loop_closure` | `true`, `false` | `true` |
| `loop_min_inliers` | count | `30` |

## Inputs and licenses
All generated by `qa/make_sequences.py`, ours: `sequences/<name>/` holds the world seed, the trajectory, and the
ground-truth poses and point clouds. Nothing is downloaded. Public datasets (TUM RGB-D, EuRoC, KITTI) are not used:
their licenses are CC BY or non-commercial.

| Sequence | What it stresses |
|---|---|
| `aisle-sweep` | long straight aisles, U-turns |
| `loop` | a closed loop around a block of shelves: loop closure |
| `figure8` | two loops, crossing in the middle |
| `figure8-fast` | the same at twice the speed: fast rotations |
| `docking` | slow approach and rotation in front of a wall |
| `long-corridor` | few features along the direction of travel: degenerate for ICP |

600 frames (40 s) each.

## Visualizations (`qaboard.yaml`)

```yaml
outputs:
  metrics: qa/metrics.yaml
  visualizations:
    - name: Trajectory
      path: poses.tsv
      type: 6dof/txt
      show_3d: true
    - name: Depth camera
      path: camera.mp4                 # played in sync with the reference
    - name: Error over time
      path: ate.plotly.json
      side_by_side: false
    - name: Map, top-down
      path: map.png                    # reconstructed map vs the true layout
    - name: Point clouds
      type: pointcloud/txt
      default_hidden: true
```

The 6DoF and point cloud viewers come from specific projects, and their file layouts are fixed in the web app:

- **6DoF** (`webapp/src/viewers/slam/SlamOutputCard.jsx`): a TSV file with a header row, a `t` column in seconds and
  one column per pose value (`x y z q_w q_x q_y q_z`; `x y z` are needed for the 3D view). The first row is skipped.
  The ground truth is read from `GT_final.txt` in the run's output directory, in the same format: always write it.
- **Point clouds** (`webapp/src/viewers/tof/TofOutputCard.jsx`, built for a ToF camera): the run's `metrics.frames`
  lists `{frame_path_idx: N}`; clouds are `Frame<N>/pointcloud.pcd` (PCD, ASCII or binary, `x y z`), the ground truth
  is `Frame<N>/pointcloud.pcd` under the input's folder, and heatmaps are `Frame<N>/<type>.hex` (W x H values, one
  per line, then `width=W` and `height=H`). The project writes keyframes in that layout.
- If the point cloud viewer can't show the result well in that layout, generalizing it is product work to decide in
  phase 3 (the docs already say these two viewers "need to be split").

## Story (`story.yaml`)
About 30 commits, mostly by mira, some by arjun. The plot: **loop closure cuts the error on loops, then a keyframe
change makes the fast figure-8 drift; History finds it, a fix restores it.**

| When | Branch | Author | Change | Shows |
|---|---|---|---|---|
| -38d | `main` | mira | **`fw-26-08`**: frame-to-frame ICP, `loop_closure: false` | milestone `fw-26.08` |
| -31d to -24d | `slam/loop-closure` | mira | **`loop-closure`**: `loop_closure: true, loop_min_inliers: 15`; merged | `loop`, `figure8`: ATE −40% or better |
| -22d | `main` | mira | **`loop-inliers`**: `loop_min_inliers: 30` | fixes a false closure on `long-corridor` |
| -20d | `main` | mira | **`fw-26-09`**: release | milestone `fw-26.09` |
| -16d | `main` | arjun | **`keyframe-dist`**: `keyframe_dist: 0.6` ("fewer keyframes, -20% time per frame") | `figure8-fast` ATE ×2 or worse; others barely move |
| -16d to -6d | `main` | both | fillers | the regression stays in History |
| -6d | `main` | mira | **`keyframe-angle`**: `keyframe_dist: 0.3, keyframe_angle: 10` | `figure8-fast` back within 10% of `fw-26-09` |
| -0d 15:00 | `main` | mira | latest commit | `ci` still running at T0 |

**Checks:** the "Shows" column. **Milestones:** `fw-26.08` and `fw-26.09`, by mira.

- The whole story: ≤ 15 min on a 4-CPU runner.
