# image-quality: the camera ISP (`kitefin/camera-isp`)

## Purpose
- **Shows:** QA-Board's image tools on a camera pipeline: synced zoom, Image Diff and its threshold, pixel values, ROI
  histograms, auto-ROI, filters, deep zoom on a 113-megapixel image, per-stage dynamic outputs, metrics with targets,
  tuning, and bit-accuracy checks of a fixed-point model.
- **Audience:** camera/ISP and imaging engineers, embedded teams handing an algorithm to silicon. It is also the
  tutorial's template (`qa init --template image-quality`), so its code stays short and readable.
- **Phase 1:** the vertical slice is built on it.

## What the code computes
Python (numpy, scipy, Pillow, tifffile). `qa/main.py` simulates the K3 camera, runs the ISP, and measures the result
against the scene it started from.

1. **Scene:** the input, converted to linear RGB.
2. **Sensor:** optics blur (Gaussian PSF), RGGB Bayer mosaic, exposure and analog gain from the configuration, shot noise
   (Poisson) and read noise (Gaussian) from a fixed noise model, black level 64, 12-bit quantization. Seeded per input.
3. **ISP**, one PNG per stage in `stages/`:
   1. black level and white balance, then the raw mosaic shown as a false-color image (`1.png`);
   2. demosaic: `bilinear` or `hamilton-adams` (edge-directed) (`2.png`);
   3. denoise: `gaussian` or `bilateral`, on luma and chroma (`3.png`);
   4. sharpen: unsharp mask with a detail boost, optionally clamped by local contrast (`4.png`);
   5. tone map (filmic curve), sRGB, 8 bits (`5.png`, also `out.png`).
4. **Measures:** PSNR and SSIM against the scene; on charts, noise in flat patches, MTF50 and edge overshoot from the
   slanted edge (ISO 12233-style ESF → LSF → MTF), ΔE2000 on the color chart.

**Platforms**
- `linux`: the float pipeline (float32).
- `hw-model`: the same pipeline as the camera chip computes it, in integers: 12-bit input, 16-bit datapath, Q-format
  coefficients, LUTs for bilateral weights and the tone curve, a configurable rounding mode. Integer math makes its
  outputs bit-exact across machines, so `qa check-bit-accuracy` can compare commits. It also writes `raw/<stage>.u16`
  (each stage's 16-bit buffer), `regs.txt` (the register values the chip would be programmed with), and
  `fxp_psnr`: PSNR of its output against the float pipeline's.

**Flags** (`build/flags.json`; defaults are the head of `main` at T0):

| Flag | Values | Default |
|---|---|---|
| `demosaic` | `bilinear`, `hamilton-adams` | `hamilton-adams` |
| `denoise` | `gaussian`, `bilateral` | `bilateral` |
| `denoise_strength` | 0.5-3.0 | `1.6` |
| `detail_boost` | 1.0-2.0 | `1.5` |
| `sharpen_clamp` | `none`, `local-contrast` | `local-contrast` |
| `tone_curve` | `gamma`, `filmic` | `filmic` |
| `tile_size` | pixels, `0` = the whole frame at once | `512` |
| `fxp_rounding` | `truncate`, `half-up`, `half-even` | `half-even` |
| `fxp_bilateral_guard_bits` | 0-4 | `2` |
| `chroma_denoise_low_light` | `true`: an extra chroma pass when gain ≥ 16 | absent |

Tuning parameters override flags of the same name (`denoise_strength`, `detail_boost`).

**Configurations** (`configs` in batches): `base` (ISO 100), `low-light` (ISO 3200), `night` (ISO 12800). They set
gain and exposure, so they show as tags on runs.

## Inputs and licenses

| Input | Source | License |
|---|---|---|
| `charts/slanted-edge.png`, `siemens-star.png`, `color-chart.png` (24 patches), `zone-plate.png`, `flat-gray.png` | Generated by `qa/make_charts.py` at first run (2 MP each) | Ours (Apache-2.0, like the repo) |
| `charts/test-wall-113mp.tiff` (12288 x 9216) | Generated: a mosaic of all charts at several scales, gradients, rendered text, and crops of the photos below | Ours, plus the photos' licenses |
| `photos/*.png`, 8 photos | Downloaded, checked, resized to 4 MP (Pillow Lanczos, deterministic) | CC0 or public domain only |

- **Photos** cover what an ISP gets wrong: `night-street` (point lights, noise), `foliage` (fine texture),
  `facade` (straight edges: moiré, halos), `sky-gradient` (banding), `warehouse-aisle` (the robot's view, mixed light),
  `fabric-colors` (saturated colors, false color), `backlit-window` (high contrast: halos), `stone-texture` (detail vs
  noise).
- **Sources:** Wikimedia Commons files tagged CC0 or public domain, US federal works (NASA, USGS, NPS, USFWS: check
  each file's page, some are credited to third parties), or photos a maintainer took and releases under CC0. Not
  ESA/Hubble (CC BY), Unsplash or Pexels (their own licenses). No identifiable person as the subject, no prominent
  logo.
- Each photo is listed in `inputs.lock.yaml` (url, SHA-256 of the original and of the resized file, bytes) and in
  `LICENSES.md` (title, author, source page, license, retrieval date). CI uses the R2 mirror.
- **ROIs:** each photo has a `<name>.metadata.yaml` (ours) with 2-3 named regions (`roi:`), read by `metadata()` in
  `qa/main.py`, so the viewer's ROI menu has presets next to the auto-ROIs.
- **113 MP output:** written as a tiled, multi-resolution TIFF (`out.tiff`), which the viewer prefers over `out.png`
  and Cantaloupe can serve as a pyramid without decoding the whole image per tile. Verify in phase 1 which pyramid
  layout (successive IFDs or SubIFDs) Cantaloupe's TIFF reader uses.

## Metrics (`qa/metrics.yaml`)

| Key | Label | Unit (`suffix`, `scale`) | `smaller_is_better` | `target` |
|---|---|---|---|---|
| `psnr` | PSNR | ` dB` | false | 30 |
| `ssim` | SSIM | | false | 0.9 |
| `noise_flat` | Noise in flat patches | ` DN` (8-bit) | true | 2.0 |
| `mtf50` | MTF50 | ` cy/px` | false | 0.25 |
| `overshoot` | Edge overshoot (halos) | `%`, scale 100 | true | 0.05 |
| `delta_e` | Color error ΔE2000 | | true | 5 |
| `fxp_psnr` | Fixed-point vs float | ` dB` | false | 45 |
| `runtime` | Runtime | ` s` | true | |
| `is_failed` | Crashed | `%`, scale 100 | true | 0 |

Chart metrics only exist on the charts they need. `default_metric: psnr`;
`summary_metrics: [psnr, ssim, overshoot, mtf50, noise_flat]`; `main_metrics: [psnr, ssim, overshoot, mtf50, runtime]`.
Gate rules (experimental): `{metric: psnr, max_regression: 1%}`, `{metric: overshoot, max_regression: 20%}`.

## Batches (`qa/batches.yaml`)

| Batch | Runs | Time on a 4-CPU runner |
|---|---|---|
| `ci` | 5 charts + 8 photos × `base`, `low-light` (26 runs) | ≤ 20 s |
| `bitexact` | `hw-model` platform: 5 charts + 2 photo crops (1 MP), `base` | ≤ 10 s |
| `deep-zoom` | the 113 MP wall, `base`, tiled over 4 processes | ≤ 3 min, ≤ 3 GB |
| `nightly` | all inputs × `base`, `low-light`, `night`, and `bitexact` | ≤ 1 min |
| `sweep-denoise` | 4 photos + slanted edge, `low-light`; meant for `--tuning-search` | ≤ 5 s per combination |

CI runs `qa batch ci`, then `qa --platform hw-model batch bitexact` and
`qa --platform hw-model check-bit-accuracy --batch bitexact`.

## Story (`story.yaml`)
About 35 commits over 6 weeks. The plot: **a denoiser that wins PSNR but adds halos**, merged because the numbers
looked good, caught in the images, fixed with a clamp.

| When | Branch | Author | Change (flags) | Shows |
|---|---|---|---|---|
| -42d to -36d | `main` | tobias, ines | pipeline basics: noise model, `demosaic: hamilton-adams`, `tone_curve: filmic` | MTF50 up, false colors down |
| -35d | `main` | ines | **`isp-4-1`**: release, `denoise: gaussian, detail_boost: 1.2` | milestone `isp-4.1` |
| -31d to -29d | `fxp/round-half-even` | tobias | **`fxp-round-half-even`**: `fxp_rounding: half-even`; merged | `check-bit-accuracy` fails (sharpen and tone-map files differ), `fxp_psnr` +0.2 dB or more |
| -24d to -21d | `isp/bilateral-denoise` | ines | **`bilateral-denoise`**: `denoise: bilateral, denoise_strength: 1.6, detail_boost: 1.5`; a local run `ines-halo`; the `tune-denoise` sweep (strength × boost, 12 combinations) | `low-light` PSNR +0.3 dB or more, noise −25% or more, **overshoot +80% or more** (about 4% → 11%) |
| -20d | `main` | ines | **`merge-bilateral`** | History: overshoot jumps |
| -14d to -10d | `isp/halo-clamp` | ines | **`halo-clamp`**: `sharpen_clamp: local-contrast`; merged | overshoot ≤ 5.5%, PSNR within 0.15 dB of `bilateral-denoise` |
| -8d | `main` | ines | **`isp-4-2`**: release | milestone `isp-4.2` |
| -6d | `main` | tobias | **`one-tile`**: `tile_size: 0` | the 113 MP run dies over its memory limit (`lsf-memlimit`) |
| -6d +3h | `main` | tobias | **`one-tile-fix`**: `tile_size: 512` | |
| -3d to -1d | `fxp/guard-bits` | tobias | **`fxp-guard-bits`**: `fxp_bilateral_guard_bits: 2` | `fxp_psnr` 43 → 47 dB or close; bit-accuracy differs, as expected |
| -0d 14:10 | `main` | ines | **`chroma-low-light`**: `chroma_denoise_low_light: true` | `ci` still running at T0 (50% done, 3 running) |

- `defaults.flags` is the state before the story: `demosaic: bilinear, denoise: gaussian, denoise_strength: 1.0,
  detail_boost: 1.0, sharpen_clamp: none, tone_curve: gamma, fxp_rounding: truncate, fxp_bilateral_guard_bits: 0`.
- `deep-zoom` runs on `isp-4-1`, `merge-bilateral`, `isp-4-2`, `one-tile`, `one-tile-fix`.
- Fillers (docs, refactors, CI) keep their parent's flags and run `ci` and `bitexact`, which stay bit-accurate.
- **Checks:** the "Shows" column, plus a hook `bit_accuracy(commit, vs, expect)` that runs `qa check-bit-accuracy`
  and expects `differ` on `fxp-round-half-even` and `fxp-guard-bits`, `same` on a filler.
- **Milestones:** `isp-4.1` on `isp-4-1` and `isp-4.2` on `isp-4-2`, by ines.

## Determinism and budget
- Fully deterministic except `runtime`: noise is seeded per input and the story seed, the integer pipeline is
  bit-exact, the float pipeline is deterministic on one machine (and close across machines).
- The whole story: ≤ 20 min on a 4-CPU runner (about 35 `ci` and `bitexact` batches, 5 `deep-zoom`, one sweep).
- First run: generating the charts and the 113 MP wall takes about a minute; they are cached in the inputs folder.
