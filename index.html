Results review for algorithm teams

Tests tell you it runs. QA-Board shows you it's better.

Every commit runs on your test set. QA-Board puts its outputs next to the reference's (images, plots, flame graphs, logs and metrics) so your team sees what changed, agrees it's better, and ships it.

You already built half of this

Every algorithm team ends up with its own tools to look at results. They fit, at first.

  • A script that renders an HTML page of images, and an output folder per run that nobody cleans up.
  • Metrics pasted into a spreadsheet, a week after someone ran them.
  • Screenshots in a chat thread, to argue which version looks better.
  • A dashboard someone maintains on weekends, for one project.

QA-Board is what those tools become after years of use on dozens of projects: one place where each commit's outputs and metrics sit next to the reference's, for everyone on the team.

The loop

Run, compare, look, find, tune, gate

The same review loop for every algorithm: camera pipelines, models, servers, embedded code.

Run your code on your test set

Wrap your code with qa and run it on a batch of inputs: on your computer, on a cluster (LSF, Dask, Celery) or in CI on every push.

Use cases

For outputs that pass/fail tests can't judge

Each use case follows a demo project: the problem, the workflow, and the configuration that produces what you see.

  • Camera, ISP, imaging

    Image quality

    A denoiser wins PSNR but adds halos: synced zoom, image differences, deep zoom on 113 MP images, every pipeline stage.

  • Performance engineering

    Serving latency

    A cache saves CPU and takes p99 from milliseconds to seconds: latency distributions, flame graph diffs, History, a tuning frontier.

  • Computer vision, ML

    Model evaluation

    An int8 detector loses small objects: metrics per class and slice, PR curves over the reference, automated tuning.

  • Embedded, HW/SW co-design

    Bit accuracy

    Check that a change left every output file identical, before you hand a model over to a hardware team.

  • Robotics, perception

    Trajectories and 3D

    6DoF trajectories against ground truth, point clouds and videos played in sync with the reference.

The details

Polish you'd never build in-house

Years of daily use on dozens of projects, in the web app you get on day one.

  • Deep zoom

    Images over 100 MP load tile by tile, from the whole image down to single pixels.

  • Image difference

    Perceptual, ΔE 2000 or per channel, with the values on the pixels: only what really changed stands out.

  • Pixel values

    Hover a pixel to read its values in both images, with a crosshair on the other.

  • Histograms

    Select a region to compare its histograms, new against reference.

  • Regions of interest

    Jump to preset regions, or to where the images differ most.

  • Filters

    Brightness, contrast and gamma on every image at once, to see into the shadows.

  • Every stage

    Sliders over a pipeline’s stages or a video’s frames, synced across runs.

  • Flame graph diffs

    The functions that got slower in red, the faster ones in blue, the new ones in orange.

  • Plot overlays

    Your Plotly figures, with the reference drawn dashed on the same axes.

  • Bit accuracy

    Only the output files that changed: click one to diff it with the reference.

  • Live logs

    Follow a running log, count its errors, jump to the next one.

  • File browser

    Every run’s folder in the browser, driven from the keyboard.

Integrations

Fits your stack

QA-Board wraps the code you have, where it runs today. It doesn't need to be the entrypoint of your build or your CI.

  • Your code

    • Python
    • Any executable: C++, shell...

  • Git and CI

    • LSF
    • Dask
    • Celery

  • Servers

    • Docker Compose
    • Kubernetes (Helm)
    • Air-gapped installs

  • Sign-in

    • Local accounts
    • LDAP
    • SAML

  • Storage

    • A shared folder (NFS, SMB...)
    • Mounted at the same path everywhere

What's new: October 2026

qaboard v1.1.1

A new image viewer, readable configuration diffs, a dark theme and a commit page that stays fast with 1000 runs. QA-Board now works with GitHub and other git hosts, and comes with a quickstart, a tutorial and a user guide. Admins: read "Before you upgrade" first; at SIRC, also install `qaboard-site-sirc` when you upgrade qaboard.

Users

A new image viewer

Compare images side by side, with a wipe, one at a time in place, or as their difference, measured perceptually or in ΔE 2000. Zoom in to read the pixels' own values, even 16-bit or raw, run a blind test, and rank the runs of a page by how much their images changed. Videos compare the same way, frame by frame.

Users

See what changed in a configuration

Runs show how their configuration differs from their reference run's, like gain: 3 → 4, and hide the settings all runs share. Lists and tuning parameters are readable, and runs are compared with the reference run whose configuration is closest. Copy a run's settings as qa options.

Fast with 1000 runs and years of commits

On a commit with 1000 runs, filtering takes half a second instead of freezing the page for 7, and the Metrics Table opens in a third of a second instead of 7. The Filter box searches all of a project's commits, and long commit lists and the projects list load as you scroll.

Dark theme and more room for results

Switch to a dark theme, or follow your system's. Collapse the sidebar to icons, dock the View options on the right (o), and switch commit lists to Compact. Press ? for the keyboard shortcuts and the filter syntax.

Logs, files and reruns

Logs update live, with search, and failed LSF runs say why LSF stopped them. Browse a run's files under /s/, edit your batches in Available Tests with errors flagged as you type, and redo only the runs you filtered, with the batch's runner and concurrency.

Project integration

GitHub, other git hosts and a quality gate

QA-Board works with GitHub and GitHub Enterprise as well as GitLab, and receives the push events of Gitea, Forgejo and Bitbucket Cloud. qa batch sets a commit status that links to the results, you can start GitHub Actions workflows from the web app, and the experimental qa gate fails the CI when quality regresses.

Admins

Deploy, monitor and upgrade safely

deployments/deploy.py rolls out new backend replicas next to the old ones and rolls back instantly, a Helm chart runs QA-Board on Kubernetes, and Sentry traces requests from the browser to the database. Before upgrading, check your git host, QABOARD_STORAGE_ROOTS and QABOARD_PROXY_HOSTS settings, and your backups.
