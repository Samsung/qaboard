Results review for algorithm teams

Tests tell you it runs. QA-Board shows you it's better.

Every commit runs on your test set. QA-Board puts its outputs next to the reference's (images, videos, point clouds, plots, flame graphs, logs and metrics) so your team sees what changed, agrees it's better, and ships it.

You already built half of this

Every algorithm team ends up with its own tools to look at results. They fit, at first.

  • A script that renders an HTML page of images, and an output folder per run that nobody cleans up.
  • Metrics pasted into a spreadsheet, a week after someone ran them.
  • Screenshots in a chat thread, to argue which version looks better.
  • A dashboard someone maintains on weekends, for one project.

QA-Board is what those tools become after years of use on dozens of projects: one place where each commit's outputs and metrics sit next to the reference's, for everyone on the team.

The loop

Run, compare, look, find, tune, gate

Run your code on your test set

Wrap your code with qa and run it on a batch of inputs: on your computer, on a cluster (LSF, Dask, Celery) or in CI on every push.

Viewers

Built for heavy data

Each kind of output gets a viewer that puts the new run next to the reference, in sync, and shows where they differ: images and videos down to the pixel, 3D maps, flame graphs, plots and reports.

Images, down to the pixel

Zoom from a 113 MP test wall to single pixels of a Siemens star, and the reference follows. The viewer loads only the tiles it shows.

  • Wipe and flipDrag a divider across the two images, or flip between them in place: differences jump out.
  • The differencePerceptual, ΔE 2000, absolute or signed. Raise its maximum until only what really changed stands out.
  • Blind testsThe two images in a random order, A and B: pick the better one, then reveal which was new.

The details

Polish you'd never build in-house

Years of daily use on dozens of projects, in the web app you get on day one.

  • Which runs changed most

    The server compares the images of every run on the page with the reference’s, and ranks the runs by their largest difference: start your review where it matters.

  • Every stage, synced

    One slider over a camera pipeline’s stages, from the raw mosaic to the output, drives every run’s card at once.

  • Bit accuracy before a hardware handoff

    Only the output files that changed, each diffed with the reference’s. A commit that changes none is bit-accurate.

  • Why a run failed

    When LSF kills a run, its log says why, compares the memory it used with what it asked for, and says what to change.

  • Tuning frontiers

    Every configuration of a sweep, one metric against another: see which ones sit on the efficient frontier.

  • The file’s own values

    Hover a pixel: its values in both images as your code saved them, 16-bit or float included, not only the colors on screen.

  • Milestones

    Save a release as a shared milestone, an experiment as a private one, and compare any commit with them.

  • Live logs

    Follow a running log, count its errors, and jump from one to the next.

  • File browser

    Every run’s folder in the browser, from the keyboard: j k to move, / to filter, c to copy a path.

Use cases

For outputs that pass/fail tests can't judge

Each use case follows a demo project: the problem, the workflow, and the configuration that produces what you see.

  • Camera, ISP, imaging

    Image quality

    A denoiser wins PSNR but adds halos: synced zoom, image differences, a 113 MP test wall, every stage of the pipeline.

  • Computer vision, ML

    Model evaluation

    An int8 detector is 72% smaller and misses small objects: metrics per class and object size, PR curves over the reference.

  • Robotics, perception

    Odometry and mapping

    A false loop closure pulls the trajectory meters away: 6DoF trajectories against the ground truth, point clouds, depth video in sync.

  • Embedded, HW/SW co-design

    Bit accuracy

    Check in CI that a change left every output file identical, before you hand a fixed-point model over to a hardware team.

  • Performance engineering

    Serving latency

    A shared cache saves CPU and takes p99 from milliseconds to seconds: latency tails, flame graph diffs, History, a tuning frontier.

  • LLM agents

    Agent evals

    Shorter tool descriptions, and an assistant reboots robots without asking: transcripts diffed, a report per task, pass rate and cost.

Users

A new image viewer

Compare images side by side, with a wipe, one at a time in place, or as their difference, measured perceptually or in ΔE 2000. Zoom in to read the pixels' own values, even 16-bit or float, run a blind test, and rank the runs of a page by how much their images changed. Videos compare the same way, frame by frame.

Users

See what changed in a configuration

Runs show how their configuration differs from their reference run's, like gain: 3 → 4, and hide the settings all runs share. Lists and tuning parameters are readable, and runs are compared with the reference run whose configuration is closest. Copy a run's settings as qa options.

Project integration

GitHub, other git hosts and a quality gate

QA-Board works with GitHub and GitHub Enterprise as well as GitLab, and receives the push events of Gitea, Forgejo and Bitbucket Cloud. qa batch sets a commit status that links to the results, you can start GitHub Actions workflows from the web app, and the experimental qa gate fails the CI when quality regresses.

Admins

Deploy, monitor and upgrade safely

deployments/deploy.py rolls out new backend replicas next to the old ones and rolls back instantly, a Helm chart runs QA-Board on Kubernetes, and Sentry traces requests from the browser to the database. Before upgrading, check your git host, QABOARD_STORAGE_ROOTS and QABOARD_PROXY_HOSTS settings, and your backups.
